## 一、背景与目标

### 1.1 背景

AI 编码助手（Claude Code 等）在软件测试领域的应用已从概念走向可落地的工程实践，可覆盖「需求评审 → 用例设计 → 自动化执行 → 报告汇总」的完整链路。测试团队已在预研环境中完成一套覆盖上述全流程的 AI 测试技能资产的建设与验证（详见第二节），具备在公司实际项目中落地应用的条件。

随着版本迭代节奏加快、回归工作量持续增长，传统人工测试模式在效率与覆盖面上逐渐承压。将预研成果转化为实际生产力，用 AI 辅助测试提效保质，是当前测试工作的现实需要。为此制定本一个月实践计划，在公司实际项目上完成 AI 自动化的了解、运用与落地实践。

### 1.2 总体目标

**一个月内，以公司系统的一个真实模块为试点，跑通「AI 需求评审 → AI 用例设计 → AI 自动化执行 → AI 统一报告」完整闭环，沉淀出可直接复用的标准交付物与作业流程（SOP）。**

实践主题「了解 → 运用 → 实践」的落地节奏：

| 主题阶段 | 承接方式                                            |
| -------- | --------------------------------------------------- |
| 了解     | 第 1 周：大模型与提示词认知、能力盘点、环境搭建     |
| 运用     | 第 2~3 周：AI 逐环节落到试点模块真实交付            |
| 实践     | 第 4 周：全流程闭环 + 效率对照度量 + 收尾周落地推广 |

### 1.3 量化目标

> 基线值于第 1 周实测回填；目标值在启动会上结合实际情况确认调整。

| # | 度量项                     | 基线（纯人工）            | 目标（AI 辅助）                                                | 度量方法            |
| - | -------------------------- | ------------------------- | -------------------------------------------------------------- | ------------------- |
| 1 | 需求评审                   | 无固定产出 / 口头意见为主 | 每份需求产出 1 份五维结构化评审报告，单份产出 ≤ 2h            | 产出物 + 计时       |
| 2 | 用例设计效率（同规模模块） | 第 1 周实测回填（人天）   | 总投入 ≤ 基线的 50%，且用例评审一次通过率 ≥ 80%              | 对照计时 + 评审记录 |
| 3 | 用例覆盖结构               | 无固定标准                | 正向 ≥ 40%、负向 ≥ 30%、边界 ≥ 20%、安全 ≥ 10%             | 25 列标准用例统计   |

| 7 | 提示词资产沉淀             | 无积累                    | 团队提示词库 ≥ 10 条场景模板（评审/用例/执行/报告），并入 SOP | 模板库统计          |

## 二、能力基础：前期预研成果盘点

### 2.1 大模型与工具组合（本月「了解」的基础对象）

AI 测试能力的底层是「大模型 + Agent 工具链 + 提示词」。本月"了解"环节首先建立对这三层的工程认知，这是全员必修的基础课：

| 层次         | 本月主力                           | 备选/可替换                 | 学习要点                                                                                        |
| ------------ | ---------------------------------- | --------------------------- | ----------------------------------------------------------------------------------------------- |
| 大模型       | Claude（Anthropic）+ 智谱 GLM      | DeepSeek、通义千问、Kimi 等 | 能力边界（擅长/不擅长）、上下文与 token 限制、幻觉现象与人工校验、多模态能力（截图/验证码识别） |
| Agent 工具链 | Claude Code（承载全部测试技能）    | Cursor 等 Agent 型编码助手  | 工具调用机制（读写文件/执行命令/驱动浏览器）、技能（Skills）= 可复用的结构化提示词包            |
| 提示词工程   | 技能文件、评审维度、用例与报告模板 | —                          | 提示词结构（角色/任务/约束/输出格式）、少样本示例、思维链、迭代调优方法                         |

组合策略：以 **Claude Code + 智谱 GLM** 为主力组合并互为备份；所有技能与提示词资产按「不绑定单一模型/工具」的原则编写，必要时可整体迁移至其他组合（如 Cursor + DeepSeek / 通义千问），避免单一供应商依赖。

### 2.2 核心能力平台（本月交付所依托）

| # | 能力                         | 覆盖环节   | 交付物形态                                                                                                   | 依托工具              |
| - | ---------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------ | --------------------- |
| 1 | AI 需求评审                  | 测试左移   | 五维评审报告（可测性 / 边界异常 / 场景状态 / 数据环境 / 阻塞点），支持 PDF/Word/MD/TXT 输入                  | Claude Code           |

| 3 | 接口自动化                   | 接口测试   | 后端源码自动提取接口文档 → 业务场景 → 可执行用例 → **pytest + Allure 自动执行报告**                 | pytest / Allure       |
| 4 | Web UI 用例执行              | 功能回归   | 表格/MD 用例 → 有头浏览器逐条执行 + 截图留痕 → **PASS/FAIL/BLOCKED 执行报告**                        | browser-use           |

### 2.3 备选技术路线（已完成调研整理，视试点情况选用）

| 路线                                 | 定位                                                                    | 适用判断                       |
| ------------------------------------ | ----------------------------------------------------------------------- | ------------------------------ |
| OpenTest 全流程方案                  | 用例设计工作流的另一实现（已吸收整合进主力工作流）                      | 仅作参考，不单独推广           |

## 五、成功度量与验收方法

1. **对照法**：选上一迭代中与试点模块规模相当的人工过程作基线（第 1 周回溯采集），同口径对比用时与产出量。
2. **质量门禁法**：AI 产物一律经人工评审确认后采用（评审通过率、修改点分类统计），质量责任仍在人。
3. **可复现法**：接口/UI 自动化各保留一轮完整报告与脚本资产，任何验收人可重跑复现。
4. **验收口径**：七个 KPI 全部有实测值；全流程闭环至少完整跑通一次；SOP 让他人能照做（种子用户验证）。

## 七、风险与应对

| # | 风险                                   | 应对                                                                                                                       |
| - | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
