# 08 · 技能详解：operation-manual（网站操作手册生成）

> **一句话**：给一个网站地址，AI 自己用浏览器逛一遍、边逛边截图，最后交给你一本**带截图的 Markdown 操作手册**（用户手册 / 使用指南 / 系统说明书）。

[← 返回总导读](README.md) | 套件自带文档：[operation-manual/使用说明.md](../../operation-manual/使用说明.md)

---

## 1. 输入：它会问你这几项

| 字段 | 必填 | 说明 |
|------|------|------|
| 网站 URL | ✅ | 起始入口 |
| 产品/系统名称 | ✅ | 手册标题 |
| 目标读者 | 否 | 默认「普通业务用户」 |
| 功能范围 | 否 | 不指定就按站点导航自动识别 |
| 补充信息 | 否 | 业务背景、术语、注意事项 |
| 登录方式 | 条件 | 需登录时：给凭据 / 你手动登录 / SSO |
| 输出路径 | 否 | 默认 `{产品名}-操作手册/` |

## 2. 六步工作流

```
Step 1 收集输入 → Step 2 规划探索范围 → Step 3 网站探索与截图
→ Step 4 生成大纲(等你确认) → Step 5 撰写手册 → Step 6 润色输出
```

**探索阶段**（用的是 playwright-cli，默认**有头**——你能看见它在逛）：
- 每个功能入口点进去 → 截图存到 `assets/`（命名 `{模块}-{步骤序号}-{简述}.png`）→ 记录步骤与 URL；
- **需要登录时**：你给凭据它代填；遇验证码/SSO → 请你在可见的浏览器窗口里手动完成，回复「已登录」它再继续；登录态临时保存，**结束时删除，不进 git**。

**大纲确认**：先给你一份只含标题与要点的目录，你说「没问题」或「直接生成」再往下写。

**成稿格式**：每步 = **目的 → 操作 → 截图 → 预期结果**；用「您」称呼读者、一步一截图；没探索到的功能标「待补充」，**不编造**。

## 3. 产物

```
{产品名}-操作手册/
├── {产品名}-操作手册.md     # 手册正文（内嵌截图引用）
└── assets/*.png             # 全部截图
```

收尾它会报告：文件路径、覆盖模块数、截图数、哪些部分「待补充」。

## 4. 使用话术

**场景 1：标准手册**
> 「给 https://oa.example.com 生成操作手册，系统叫"智慧 OA"，重点覆盖请假和报销流程」

**场景 2：需要登录**
> 「给 https://xxx.com 生成操作手册，账号 test01 密码我等下在浏览器里自己输（有验证码）」

**场景 3：testflow 收尾顺手出手册**（阶段 5 可选项）
> 「变更归档后，顺手给被测系统 https://test.example.com 生成一份操作手册」

## 5. 注意事项

- **首次运行**可能自动下载浏览器（5–15 分钟，仅一次）；
- 手册里**绝不会出现**账号密码/内部 API/源码（硬规矩）；
- 工具链边界：本技能用 **playwright-cli**；UI 测试用 **browser-use**——两条独立工具链，勿混用（仓库级约定）。

## 6. 质量检查清单（交付前它自查，你也可以拿来验收）

- [ ] 每个功能模块有清晰入口说明
- [ ] 关键步骤均有截图且路径正确
- [ ] 步骤可独立执行，不依赖隐含知识
- [ ] 无账号密码等敏感信息
- [ ] 术语与你给的补充信息一致
- [ ] 未探索到的功能标「待补充」而非编造
