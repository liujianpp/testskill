# 02 · 技能详解：prd-review（测试视角需求评审）

> **一句话**：拿到产品经理的 PRD 后，让 AI 站在**测试角度**挑毛病——需求能不能测、边界漏没漏、状态全不全、测试数据好不好造、有没有卡住测试的坑。

[← 返回总导读](README.md) | 套件自带文档：[prd-review/使用说明.md](../../prd-review/使用说明.md)

---

## 1. 它是什么 / 不是什么

| ✅ 它做 | ❌ 它不做 |
|--------|----------|
| 只从**测试视角**评审需求文档 | 不做产品向 / 研发向的 PRD 评审 |
| 按 **5 个固定维度**全量评审 | 不只评其中一两个维度 |
| 输出结构化 Markdown 评审报告 | **不生成测试用例**（那是 spectest 的活） |

## 2. 输入与输出

| 项目 | 说明 |
|------|------|
| 输入 | `.pdf` / `.docx` / `.md` / `.txt` 文件路径，或直接在对话里粘贴需求正文 |
| 正文抽取 | pdf/docx 走脚本自动抽取（依赖 pdfplumber、python-docx）；md/txt 直接读 |
| 输出 | Markdown 评审报告，默认当前工作目录 `test-review-report.md`（可指定路径） |
| 抽取失败 | 扫描件没文字层 / 加密 / 损坏 → 明确报错，**禁止编造**文档内容 |

## 3. 工作流程（7 步，AI 自动走）

```
1 抽取正文 → 2 确认元信息(标题/版本/作者，不足则注明假设) → 3 提炼需求速览
→ 4 按 5 维全量评审 → 5 总体结论 → 6 按模板落盘 → 7 只回复报告路径
```

**「需求速览」长什么样**（写在报告开头，帮你 1 分钟看懂需求）：

| 小节 | 内容 |
|------|------|
| 需求在讲什么 | 1–3 句：业务目标、范围内/外 |
| 端与角色 | 表格：端/角色、使用者、能力边界 |
| 功能模块 | 表格：模块、端、测试关注点一句话 |
| 核心业务主流程 | 1 张 Mermaid 流程图（最多 2 张图） |

## 4. 五个评审维度（全部评审，缺一不可）

| # | 维度 | 它在查什么（举例） |
|---|------|-------------------|
| 1 | **可测性与验收标准** | 核心需求能否写成可判定的验收条件（Given/When/Then）；有没有「体验良好」「适当处理」这种没法验证的话；关键阈值有没有数字 |
| 2 | **边界与异常** | 空值/超长/非法字符；未登录/权限不足；超时重试；重复提交/幂等；分页上限；删数据前有没有确认 |
| 3 | **场景与状态** | 主流程步骤全不全；取消/中断/返回/二次进入的分支；状态怎么定义怎么迁移；不同角色/多端差异 |
| 4 | **数据与环境依赖** | 测试要什么账号/配置/开关；外部依赖标了没；测试数据能不能造/能不能 mock；要不要清理回滚 |
| 5 | **测试阻塞点** | 有没有开放问题卡住测试设计；规则自相矛盾；缺权限缺账号缺工具；明确列出不可测点 |

每个维度先给结论（**通过 / 有条件通过 / 不通过**），再列问题表；没问题就写「未发现问题」。

## 5. 报告里的问题长什么样

**每条问题必含 4 个字段**：级别、原文依据（章节名或摘录）、问题描述、修改建议。

| 级别 | 含义 | 你该怎么办 |
|------|------|-----------|
| `阻断` | 不补齐就没法设计/执行关键测试 | **必须**先找产品补齐 |
| `重要` | 测试设计前应处理 | 尽快确认 |
| `建议` | 可排期完善 | 记录跟踪 |

**总体结论**：有任意「阻断」→ 不通过；无阻断但有「重要」→ 有条件通过；只有「建议」→ 通过。

## 6. 怎么用（照抄话术）

**场景 1：常规评审一份 PRD**
> 「对 docs/PRD-积分商城v2.docx 做测试视角的需求评审，报告输出到 docs/评审/积分商城v2-评审报告.md」

**场景 2：直接粘贴文字**
> 「下面是我们这期需求，帮我评审一下：……（粘贴正文）……」

**场景 3：作为 testflow 全流程的第一步**（不用单独调，说跑 testflow 它自动被调用）
> 「跑一次完整 testflow，需求文档在 docs/PRD.pdf，被测地址 https://test.example.com」

## 7. 和其他技能的关系

- **下游是 spectest**：评审报告会被登记到 spectest 变更的 `proposal.md` 作为输入附件；「阻断」问题最好先解决再设计用例；
- **在 testflow 里**：它是阶段 1（需求评审），产物路径会暂存，阶段 2 开始前自动附给 spectest-new。

## 8. 常见问题

**Q：PDF 是扫描件怎么办？**
A：没有文字层就抽不出内容，技能会明确报错而不是瞎编。解决：找产品要素材 Word 版，或先用 OCR 工具转成文字版。

**Q：报告输出在哪？**
A：默认当前工作目录 `test-review-report.md`；也可以在话术里指定路径。

**Q：需求太长，一次评不完？**
A：可以直接说「分段评审，先评第 1-3 章」，AI 会按章节处理。
