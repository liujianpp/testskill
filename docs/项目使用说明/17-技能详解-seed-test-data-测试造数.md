# 17 · 技能详解：seed-test-data（测试造数）

> **一句话**：给它接口文档 / HAR 抓包 / curl / 表结构，它生成可直接用的 **Postman Collection、SQL（新增+回滚成对）、Excel 造数表、可执行 Python 造数脚本**——测试数据带 `QA_` 前缀可追溯、唯一字段自动防重、回滚按精确业务键删除。**只出文件，绝不执行**。

## 1. 解决什么痛点

| 传统造数方式 | 痛点 |
|--------------|------|
| 页面手动点 | 反复点击、耗时 |
| 手写 SQL 插库 | 字段多、关联多、容易乱、难回滚 |
| 手动拼接口调用 | 同场景反复写、重复易错 |

seed-test-data 一键生成四种产物：数据**可标识（QA_ 前缀）、可追溯（交付清单）、可回滚（精确键删除）**。

## 2. 输入与输出

| 输入（四选一或组合） | 输出（可多选） |
|---------------------|----------------|
| ① 接口文档（Swagger/OpenAPI、Markdown、截图、已有 Postman） | Postman Collection + Environment（文件夹分「造数/校验/回滚」，id 变量串联） |
| ② `.har` 抓包（自动滤静态资源/OPTIONS、去重、先出摘要） | SQL：`-01_seed.sql` + `-02_rollback.sql` **成对**（你手工在测试库执行） |
| ③ curl 粘贴 / `.sh` / `.curl` / `.txt` | Excel 造数表（评审/留档） |
| ④ 表结构（DDL / `SHOW CREATE` / 字段说明表） | Python HTTP 脚本 `script/{场景}-api-seed.py`（`seed` / `rollback` 子命令） |

**硬对应**：Postman/Python 需接口侧输入；SQL 需表结构；仅接口/HAR/curl **禁止出 SQL**；Excel 永远可出。

## 3. 工作流程（4 步）

```
① 解析输入（出「造数清单」）→ ② 勾选范围/画像/数量/格式（只问这一次）→ ③ 生成 + 自动校验 → ④ 交付清单
```

- **清单**含单资源与**串联链路**（如 `公寓→房间→租客→入住`，标「推荐」）；一条画像数据贯穿整链、ID 互指；
- 默认假设（不连环追问）：范围=主链路；画像=正常+1 异常；数量=每种 1 条；前缀=`QA_YYYYMMDD_`；
- **唯一字段防重**：身份证/手机/邮箱/唯一单号加随机段（禁止固定序号），Python 每次运行用 `secrets` 现场生成并打印清单；
- 生成后跑 `validate_artifacts.py` 自检，失败先改再交付。

## 4. 红线（必知）

1. **只出文件不执行**：不连任何库、不调真实接口、不替你跑脚本/SQL；禁止生成连库的 `*-db-seed.py`；
2. **SQL 必有成对回滚**；回滚禁止 `TRUNCATE`、禁止无 WHERE 的 `DELETE`、禁止 `LIKE 'QA_..._%'` 模糊删（用本批精确业务键 `IN (...)`）；
3. 接口侧没有删除/取消接口时，明确告知「无法接口回滚」。

## 5. 使用话术

**场景 1：接口文档造数（最常用）**
> 「根据 docs/api-docs.md 造一套完整数据：公寓→房间→租客→入住，正常+异常各 1 条，要 Postman 和 Excel」

**场景 2：HAR 抓包造数（没文档时）**
> 「用 files/flow.har 造数，先给我摘要勾选」

**场景 3：curl 快速造数（临时）**
> 「粘贴几条 cURL（如下），帮我生成 Python 造数脚本」

**场景 4：表结构造数（走 SQL）**
> 「按这几张表的 DDL 造 2 套数据（1 正常 1 异常），出 SQL 新增+回滚和 Excel」

## 6. 产物怎么用

| 产物 | 用法 |
|------|------|
| Postman | 导入后 Runner 一键跑整链；环境变量自动传 id |
| SQL | **你手工**在测试库执行：先 `01_seed` 造数；回滚在改数据**之前**执行 `02_rollback` |
| Excel | 给团队评审 / 留档数据画像 |
| Python | 复制 `.env.example` → `.env` 填 `SEED_BASE_URL`/`SEED_TOKEN` → `python3 script/xx-api-seed.py seed`（回滚 `rollback`） |

## 7. 与其他技能的关系

- 上游：`api-doc-generator`（04 册）产出的接口文档可直接喂给它；
- 下游：造好的数据服务于三支线执行（接口/Web UI/小程序）与手工测试的**前置数据准备**——如 testflow 各支线执行前先造数；
- 与 ApiAutoTest2.0 内置造数三层的区别：那是**用例内步骤**，本技能是**独立的造数文件交付物**。

## 8. 常见问题

**Q：它会把数据插进库吗？**
永不，只生成文件；执行权始终在你手里。

**Q：造的数据以后怎么清？**
交付清单列出关键唯一值与查找方式（如 `username IN ('QA_..._a1b2c3')`）；SQL 回滚按本批精确键删，不会误删别人的数据。

**Q：输入只有接口文档能出 SQL 吗？**
不能（没有表结构不写 SQL）；想出 SQL 就补 DDL。
