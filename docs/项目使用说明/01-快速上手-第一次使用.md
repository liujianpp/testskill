# 01 · 快速上手：第一次使用

> **本册目标**：从零开始，把环境准备好、搞懂目录关系、学会触发技能，并亲手跑通第一个技能。
> 前置知识：会用电脑、会打字，不需要会编程。

## 1. 第一步：安装必要软件

| 软件 | 用途 | 必装？ | 检查命令（终端里输） |
|------|------|--------|----------------------|
| Claude Code | AI 助手本体（命令行 / VSCode 插件） | ✅ 必装 | `claude --version` |
| Python 3.10+ | 跑各技能的 Python 脚本 | ✅ 必装 | `python --version` |
| uv | spectest 套件专用的 Python 包管理器 | ✅ 必装 | `uv --version` |
| Node.js + npm | 小程序 / Playwright / testerarmy-e2e 需要 | ⭕ 按需 | `node -v` |
| Git | 版本管理 | 建议 | `git --version` |
| 微信开发者工具 | 仅小程序支线需要 | ⭕ 按需 | — |

**uv 安装（Windows）**：

```powershell
powershell -c "irm https://astral.sh/uv/install.ps1" | iex
```

> 装完重开终端，再跑 `uv --version` 确认。

## 2. 第二步：搞懂「两个目录」（最重要的概念）

| 目录 | 角色 | 你什么时候碰它 |
|------|------|----------------|
| `E:\AI\skills\`（本仓库） | **开发目录**：技能在这里编写、调试；同时存放测试资产库 | 修改技能本身、查看资产时 |
| `C:\Users\admin\.claude\skills\` | **使用目录**：Claude Code 实际加载技能的地方 | 日常使用不用碰；知道技能文档里的路径指的是这里即可 |

> ⚠️ 技能文档（SKILL.md）里写死的 `.claude/skills/<技能名>/...` 路径，指的都是**使用目录**（部署后的路径），不是本仓库。

---

## 3. 第三步：技能部署同步（改过技能必须做）

在本仓库修改任何技能后，**必须**执行同步脚本把它复制到使用目录，否则改动不生效：

```powershell
powershell -ExecutionPolicy Bypass -File e:\AI\skills\spectest\spectest\sync_skills.ps1
```

> ⚠️ **已知坑**：sync 脚本内部的 `$SourceDir` 可能还指向旧路径 `E:\AI\spectest\spectest`。执行前先打开脚本确认是否为 `E:\AI\skills\...`，不是就先改过来。
> 如果你只是**使用**技能、没改过技能，一般不需要重新同步（上次同步过的还在）。

---

## 4. 第四步：在哪里「对话」很关键

| 你要做的事 | 在哪个目录打开 Claude Code | 原因 |
|------------|--------------------------|------|
| 测试某个项目（评审需求/设计用例/执行测试） | **被测项目的根目录** | spectest 的状态、报告都落在被测项目的 `spectest/changes/<变更名>/` 下 |
| 维护技能本身 / 查看测试资产库 | 本仓库 `E:\AI\skills` | 技能源码和资产库在这 |

> 小白最容易犯的错：在被测项目之外随便找个目录开聊——结果产物全落到错误位置。**先 cd 到正确目录再启动 Claude Code。**

---

## 5. 第五步：学会三种触发方式

### 方式一：自然语言（推荐新手）

直接说大白话，说到「触发词」AI 就自动启用技能：

| 你说 | 触发的技能 |
|------|-----------|
| 「帮我评审这份需求文档 docs/PRD.pdf，从测试角度」 | prd-review |
| 「根据需求生成测试用例」 | spectest 系列 |
| 「执行这份测试用例表 test.xlsx，网址是 https://xxx」 | browser-use-case-runner |
| 「扫一下后端源码，生成接口文档」 | api-doc-generator |
| 「给这个网站做个操作手册：https://xxx」 | operation-manual |
| 「跑一次完整测试流程，从需求到报告」 | testflow |

### 方式二：斜杠命令（精确点名）

对话框输入 `/`，会弹出可用技能列表，如 `/spectest-generate`、`/prd-review`、`/testflow`。

### 方式三：@技能名（部分技能强制要求）

有些技能设置了「不许 AI 自动触发」（防止误启动），必须显式点名：`@miniprogram-script-author`、`@miniprogram-run`、`@e2e-init` 等。

> 💡 **新手建议**：先自然语言；AI 理解偏了再用 `/` 或 `@` 精确点名。

## 6. 第六步：亲手跑通第一个技能（三选一）

### 练习 A：评审一份需求文档（最简单，5 分钟）

1. 准备一个 `.md` / `.txt` / `.pdf` 需求文档（随便什么内容）；
2. 在该文档所在目录打开 Claude Code，说：

> 「对 需求文档.md 做测试视角的需求评审」

3. 等它输出 → 得到 `test-review-report.md`。✅ 跑通了！

### 练习 B：让 AI 在浏览器里执行一条用例（眼见为实）

在任意工作目录打开 Claude Code，直接说：

> 「手动给你一条用例执行：用例编号 TC-001，名称「打开百度搜索」，前置条件：无，步骤：1. 打开 https://www.baidu.com 2. 在搜索框输入"天气" 3. 点击百度一下，预期结果：出现搜索结果页」

AI 会先问你几个简短问题（会话策略等），回答后它会打开一个**看得见的浏览器**窗口演示执行，最后给你报告路径和截图。

### 练习 C：给一个网站生成操作手册

> 「给 https://example.com 生成一份操作手册」

（首次运行可能要下载浏览器，约 5–15 分钟，耐心等。）

## 7. 常见坑与排雷（新手高频翻车点）

| 症状 | 原因 | 解决 |
|------|------|------|
| 说了触发词但技能没启用 | 技能没同步到使用目录 | 见 §3 同步；或用 `/技能名` 点名 |
| spectest 脚本报错 `uv: command not found` | uv 未装或终端没重开 | 装 uv（§1）并重开终端 |
| uv 脚本报依赖缺失 | 没建虚拟环境 | 先 `uv sync --project "<技能目录>"` |
| Bash 里 `SKILL_DIR` 变量不生效 | 变量赋值和 `uv run` 分成了两次调用 | **必须写在同一条命令里**：`SKILL_DIR="..."; uv run --project "$SKILL_DIR" python ...` |
| 小程序跑不起来 | Windows 的微信开发者工具路径配错 | `miniprogram.local.config` 的 `cliPath` 必须是**本机真实安装路径**（文档示例是 macOS 的，不可用）；并在开发者工具中开启服务端口 |
| UI 执行的录屏行为与预期不符 | runner-config.json 模板里 `videoRecording.enabled` 为 `true`，与文档默认（false）不一致 | 每轮生成 run-config 后核对取值，或把模板改回 `false` |
| 找不到测试产物 | 在错误目录开的对话 | 见 §4；spectest 产物在被测项目 `spectest/changes/<变更名>/` |

## 8. 环境变量怎么设（账号密码的正确姿势）

所有技能都**禁止**把账号密码写进文件，一律用环境变量。Windows 下三种设法：

```powershell
# 临时（当前终端有效）
$env:MP_ACCOUNT = "test01"

# 永久（写入用户环境，重开终端有效）
setx MP_ACCOUNT "test01"

# 文件式（推荐长期用）：各套件的 .env 文件
# 例：test-automation/api/config/.env（从 .env.example 复制后填写）
```

常用变量速查：`MP_ACCOUNT` / `MP_PASSWORD`（小程序）、`BASE_URL`（接口/界面）、`ADMIN_PASS` 等账号类（接口）、`WEB_USERNAME` / `WEB_PASSWORD`（web-script-author）。

## 9. 常用命令速查（高级用法，AI 一般会自己跑）

```bash
# spectest 系脚本（必须 uv；SKILL_DIR 赋值与 uv run 同一条命令）
SKILL_DIR="e:/AI/skills/spectest/spectest/<skill-name>"
uv run --project "$SKILL_DIR" python "$SKILL_DIR/scripts/<script>.py" [参数]

# 接口执行（直接 python）
python ApiAutoTest2.0/api-test-runner/scripts/run_tests.py --cases-json <cases.json> [--base-url <url>] [--serve]

# UI 用例导出与当轮配置（在被测项目根目录）
python3 .claude/skills/browser-use-case-runner/scripts/test_cases_export.py xlsx test-data/用例.xlsx -o reports/cases.jsonl
python3 .claude/skills/browser-use-case-runner/scripts/generate_run_config.py \
  --jsonl reports/cases.jsonl --source "xlsx:<路径>" \
  --defaults .claude/skills/browser-use-case-runner/runner-config.json

# 资产分拣与晋级（在 test-automation/ 下）
uv run --with openpyxl python scripts/promote_cases.py --input <25列.xlsx> --version 2026Q4-xxx [--dry-run]
uv run --with openpyxl python scripts/promote_iteration.py --version 2026Q4-xxx [--confirm]
```
