# seed-test-data 使用说明

**测试造数**技能（Claude Code / Cursor 通用）：根据接口文档、HAR 抓包、curl 命令或表结构，生成可直接使用的 **Postman Collection、SQL（新增 + 回滚成对）、Excel 造数表、可执行 Python HTTP 脚本**。**只出文件不执行**——不连生产库/测试库、不调真实接口、不替你跑脚本或 SQL。方案原文见 [原文-测试人必备-快速基于接口文档表结构进行造数.md](原文-测试人必备-快速基于接口文档表结构进行造数.md)。

---

## 1. 输入与输出

| 项 | 说明 |
|----|------|
| 输入（四选一或组合） | ① 接口文档（Swagger/OpenAPI、Markdown、截图、已有 Postman）；② `.har` 抓包；③ curl 粘贴或 `.sh`/`.curl`/`.txt`；④ 表结构（DDL、`SHOW CREATE`、字段说明表） |
| 输出 | Postman Collection + Environment / SQL（seed + rollback 成对）/ Excel 造数表 / Python HTTP 脚本（`script/{场景}-api-seed.py`） |
| 输出目录 | 你指定，否则当前工作目录；Python 脚本统一放 `script/` 子目录 |

**格式与输入的硬对应**：选 Postman / Python 必须有接口侧输入（文档/HAR/curl）；选 SQL 必须有表结构；**仅接口/仅 HAR/仅 curl 禁止出 SQL**；Excel 任何输入都能出。

## 2. 工作流程（4 步）

```
① 识别解析输入 → ② 勾选范围/画像/数量/格式（只问这一次）→ ③ 按模板生成 + 自动校验 → ④ 交付清单
```

1. **解析输入**：识别模块/接口/表、必填字段、鉴权、删除/取消接口、外键关联 → 得到「造数清单」（单资源 + 串联链路）。大文件先跑摘要（`summarize_har.py` / `summarize_curl.py`）防刷屏；字段不明标「待确认」给示例值，不停下追问。
2. **勾选（只问一次）**：范围（单资源 / **串联链路**「推荐」 / 都要）、画像（正常 / +异常 / +边界）、数量、产物格式。首条消息已写清则跳过直接生成。
3. **生成**：标识前缀统一 `QA_YYYYMMDD_`；唯一约束字段（身份证/手机/邮箱/唯一单号等）**必须随机化防重复**（禁止固定序号）；生成后跑 `validate_artifacts.py` 自检，失败先改再交付。
4. **交付**：只报路径 + 交付清单模板（场景/前缀/画像/关键数据表/文件清单/运行方式/回滚说明），不把文件全文贴进对话。

## 3. 硬规则（红线）

- 只出文件：**不执行 INSERT/DELETE、不调真实接口、不连任何库**；禁止生成 `*-db-seed.py` 连库脚本
- SQL 产物必须**成对**（seed + rollback），缺回滚不算完成
- 回滚只删本次标识数据：禁止 `TRUNCATE`、禁止无 WHERE 的 `DELETE`、禁止 `LIKE 'QA_..._%'` 模糊删（用本批精确业务键 `IN (...)`）
- 接口侧无删除/取消接口时：回滚文件夹可空 / Python `rollback` 明确失败提示，并在说明里写明
- 产物格式**以你勾选为准**，未选才走推荐默认

## 4. 默认假设（信息不足时，不再连环确认）

| 项 | 默认 |
|---|---|
| 范围 | 有主链路选**串联链路**；否则主资源（创建类接口 / 核心表） |
| 画像 | 正常 + 1 条异常 |
| 数量 | 每种画像 1 条 |
| 前缀 | `QA_YYYYMMDD_`（当天） |
| 未勾选格式 | 仅接口/HAR/curl → Postman + Excel + Python；仅表结构 → SQL + Excel；接口侧 + 表结构 → 全家桶 |

串联规则：选链路时一条画像数据**贯穿整链**（ID 互指）；只选子资源时自动补链路前置并在交付说明里写明。

## 5. 产物与运行

| 产物 | 文件 | 怎么用 |
|------|------|--------|
| Postman | `{场景}-seed.postman_collection.json` + `_environment.json` | 导入 Postman，文件夹分「造数/校验/回滚」，请求按依赖排序、id 走变量，Runner 一键整链 |
| SQL | `{场景}-01_seed.sql` + `{场景}-02_rollback.sql` | **你自己在测试库手工执行**（先 seed 后用，回滚先于手改数据执行） |
| Excel | `{场景}-seed.xlsx` | 评审 / 留档 |
| Python | `script/{场景}-api-seed.py` | 配 `.env`（仅 `SEED_BASE_URL` / `SEED_TOKEN`）后：`python3 script/xx-api-seed.py seed` / `rollback` |

## 6. 使用话术

**场景 1：接口文档造数**
> 「根据 docs/api-docs.md 造一套完整测试数据：公寓→房间→租客→入住，正常+异常各 1 条，要 Postman 和 Excel」

**场景 2：HAR 造数**
> 「用抓包 files/flow.har 造数，先给我摘要勾选」

**场景 3：curl 造数**
> 「粘贴几条 cURL（如下），帮我生成 Python 造数脚本」

**场景 4：表结构造数**
> 「按这几张表的 DDL 造 2 套数据（1 正常 1 异常），出 SQL 新增+回滚和 Excel」

## 7. 常见问题

**Q：它会替我把数据插进库吗？**
永不。SQL 由你手工在测试库执行；Python 脚本也是你自己跑。Skill 只负责生成文件。

**Q：造的数据怎么认出来 / 怎么清理？**
可搜字段统一 `QA_日期_` 前缀；交付清单列关键唯一值与查找方式；回滚按本批精确业务键删除，不会误删。

**Q：和 ApiAutoTest2.0 的造数三层什么关系？**
那边是接口测试用例内的「准备→验证→清理」步骤；本技能是**独立出造数文件**（Postman/SQL/Excel/Python），产出可直接给手工测试、接口执行、UI 执行前的数据准备用。

## 8. 与工作区其他套件的关系

- 上游输入可来自 `api-doc-generator` 产出的接口文档；
- 产出的数据服务于三条执行支线（接口 / Web UI / 小程序）与手工测试的数据准备；
- 解析/模板细则见 [references/](references/)（parse-api / parse-har / parse-curl / parse-schema + 四种产物模板）。
