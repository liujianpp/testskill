# 表结构解析

从 DDL 或字段说明抽出表、约束和插入顺序。禁止臆造不存在的列。

## 支持的材料

- `CREATE TABLE` / `SHOW CREATE TABLE`
- 字段说明表（列名、类型、是否为空、说明）
- ER 图文字说明、迁移脚本

只有字段中文名没有英文列名时，保留中文说明，列名用文档里的英文；文档没有英文则在交付假设里声明「列名按拼音/推测」，并在 SQL 里用注释标出。

## 每张表记录

| 项 | 说明 |
|---|---|
| 表名 | 含库名则记下，SQL 里只写表名（除非用户指定库） |
| 主键 | 自增则 INSERT 不写 id，回滚用本批精确业务键或主键列表 |
| 唯一键 | 造数时保证不碰撞；回滚优先按这些唯一键精确删 |
| 非空且无默认值 | 必须填 |
| 外键 / 关联列 | 决定插入与删除顺序 |
| 状态/类型枚举 | 用于正常 vs 异常画像 |

## 插入、回滚与串联链路

1. 按外键画出依赖：被引用的表先插，后插的表先删。
2. 无物理外键但有 `user_id`、`order_id`、`apartment_id` 这类列，同样当依赖处理。
3. 自引用（如 `parent_id`）先插父行，回滚先删子行。

把最长外键主路径列为一条「串联」勾选项（标推荐），与单表、都要一起抛出。用户只选了子表时，自动补上缺失的父表，并在假设里说明。

选了串联时：同一条画像数据贯穿整条链（同一序号的公寓 / 房间 / 租客 / 入住互相关联），不要拆成互不相关的独立行。

## 勾选清单示例

```
可造数表（回复序号或表名即可）：
1. apartment（主表）
2. apartment_room（依赖 apartment）
3. tenant
4. tenant_lease（依赖 apartment_room + tenant）
5. 串联：apartment → apartment_room → tenant → tenant_lease（推荐）
6. 都要

画像默认：正常 + 异常，各 1 条。要改请一并说明。
```
## 取值约定

与接口侧保持同一前缀 `QA_YYYYMMDD_`。

- 字符串业务键、用户名、备注：带前缀 + 随机段，既可搜又便于精确 `IN` 回滚
- **唯一键列**（`id_card`、`phone`、邮箱、唯一单号等）：必须用随机段，保证多次造数不碰撞；见 [parse-api.md](parse-api.md)
- 手机 / 邮箱 / 身份证：同 [parse-api.md](parse-api.md) 缺字段取值（随机，非固定序号）
- 金额、库存：正常为正数；异常为 0、负数或超字段精度
- 状态列：正常取「有效/待支付/上架」等可测主路径的值；异常取冻结、取消、过期、删除标记
- `datetime`：正常用当前时间；过期数据写明确的过去时间
- 布尔：正常 `1`；异常按场景给 `0`（如未启用账号）

回滚 WHERE 必须能唯一定位**本批**数据：优先 `列 IN (...本批精确业务键...)`（唯一键优先），其次 seed 文件头注释中的主键列表；**禁止**用 `LIKE 'QA_YYYYMMDD_%'` 做 DELETE。细则见 [sql-template.md](sql-template.md)。
