# playwright-cli-testcase 1.0.1 使用说明

playwright-cli-testcase 是一个**探索式 Web 测试用例生成**技能（Claude Code / Cursor 通用）：用 `playwright-cli` 真实打开被测网站探索界面，结合可选的需求文档，**先生成测试点、经用户确认后**再展开完整测试用例并导出 Excel（默认）或 XMind。

- 输入：**URL 必填** + 需求文档可选（`.md` / `.txt` / `.docx` / `.pdf` 或粘贴文本）
- 产出：`{简称}-test-plan.md`（测试点计划）→ 确认后 → `{简称}-web-testcases.xlsx`（及可选 `.xmind`）
- **不生成** Playwright 自动化脚本（`.spec.ts`）

> 目录说明：本压缩包解压后真正的技能在 `playwright-cli-testcase/` 子目录；`__MACOSX/` 为 macOS 打包残留，可删除。部署时复制 `playwright-cli-testcase/` 这一层到 `.claude/skills/` 或 `.cursor/skills/`。

---

## 1. 技能结构

```
playwright-cli-testcase/
├── SKILL.md                    # 主工作流
├── references/
│   ├── excel-columns.md        # Excel 10 列字段定义与 JSON 顶层结构
│   ├── test-methods.md         # 用例设计方法（等价类/边界值/判定表/场景法…）+ Web 专项维度
│   └── plan-template.md        # 测试点计划模板（含「需求 vs 界面」三块拆分）
└── scripts/
    ├── export_excel.py         # cases.json → .xlsx（依赖 openpyxl）
    ├── export_xmind.py         # cases.json → .xmind（仅标准库 zipfile/xml，无第三方依赖）
    └── requirements.txt        # openpyxl>=3.1.0
```

## 2. 核心工作流（四步）

```
① 解析输入 ──► ② playwright-cli 探索界面 ──► ③ 出测试点计划（必须等用户确认）──► ④ 展开用例并导出 Excel/XMind
```

### ① 解析输入
- 有需求文档：抽取功能模块、角色/权限、主流程、规则/校验、异常、数据约束，再对照界面验证。
- **无需求文档：不索要**，直接按 URL 自主探索推断功能，计划中标明「基于界面探索推断」。
- 账号/环境信息不足时做少量假设写入「假设说明」，不反复追问（**登录墙除外**）。

### ② 用 playwright-cli 探索
前置安装：
```bash
npm install -g @playwright/cli@latest
playwright-cli install-browser
```
常用命令：
```bash
playwright-cli open <url> --headed   # 默认有头模式
playwright-cli snapshot              # 可加 --depth=N 控制深度，避免撑爆上下文
playwright-cli find "关键词"
playwright-cli close
```
探索规则：
- 盘点导航、菜单、表单、弹窗、列表、空态；无需求时覆盖**一级可达页面**、深度默认 2 层。
- **遇登录**：停下问测试账号；禁止猜密码、绕过鉴权、拦截或伪造验证码接口。
- **遇纯字符图片验证码**：截图 → 当前模型识别 → 回填，只自动尝试一次；失败或滑块/点选/短信等类型则保持浏览器打开等人工完成后回复「继续」。
- 破坏性操作（删全量、支付真单）、外链、登出：跳过或只记测试点不实操。

### ③ 先出测试点，硬门禁
- 产出 `{需求简称或页面标题}-test-plan.md`，测试点 `TP_001` 起编号，覆盖正常/异常/边界/UI。
- **本阶段不写用例**（无 TC 编号、无完整步骤/预期）。
- **有需求时**「需求 vs 界面」必须拆三块：
  1. **已对齐**：一致项压缩列举
  2. **不一致**：对照表（需求怎么写 | 界面实际怎样 | 验收基准 | 对应测试点）——**验收基准必须由用户选**（按需求/按界面），技能不得替用户拍板；未选定前不得发出「请确认测试点」终态
  3. **探索未实操**：缺账号、未点破坏性操作等，写原因 + 是否保留测试点 + 执行前置
- **硬门禁**：测试点未获用户「确认」→ 禁止导出、禁止生成完整用例。

### ④ 确认后生成用例并导出
将确认后的测试点展开为统一 `cases.json`：
```json
{
  "title": "需求名或页面标题",
  "assumptions": "可选：假设说明",
  "cases": [
    {
      "case_id": "TC_001", "module": "模块名", "title": "用例标题",
      "priority": "P0", "precondition": "前置条件",
      "steps": "1. ...\n2. ...", "expected": "1. ...\n2. ...",
      "method": "场景法+边界值", "page": "/login", "notes": ""
    }
  ]
}
```
导出命令（`SKILL_DIR` = 技能目录）：
```bash
pip3 install -r "$SKILL_DIR/scripts/requirements.txt"   # 首次：openpyxl

# Excel（默认）
python3 "$SKILL_DIR/scripts/export_excel.py" <cases.json> <output.xlsx>

# XMind（用户明确要求时）
python3 "$SKILL_DIR/scripts/export_xmind.py" <cases.json> <output.xmind>
```
默认文件名：`{需求简称或页面标题}-web-testcases.xlsx`（及同名 `.xmind`），输出到当前工作目录或用户指定路径。

## 3. Excel 产物格式（10 列）

Sheet 名 `测试用例`，首行冻结，步骤/预期在单元格内换行分隔：

| 列 | 说明 |
|----|------|
| 用例编号 | `TC_001` 起 |
| 模块 | 功能子系统名（如「登录」「订单列表」） |
| 用例标题 | 一句话说明测什么 + 条件，禁止「测试xxx」空标题 |
| 优先级 | 仅 `P0`（冒烟）/ `P1`（核心）/ `P2`（次要） |
| 前置条件 | 账号、数据、环境、入口页；无则写「无」 |
| 测试步骤 | 编号步骤，每步一个动作 |
| 预期结果 | 可观察、可判定 |
| 设计方法 | 如「等价类」「边界值+场景法」，必填可组合 |
| 页面 | 页面路径/标题/路由（如 `/login`） |
| 备注 | 风险、依赖、数据准备；可空 |

## 4. 质量红线

- 步骤可执行、预期可判定；禁止「验证功能正常」类空用例
- 至少覆盖：正常路径、关键异常、关键边界（按模块体量裁剪）
- 每条用例必标 `method`；优先级仅 P0/P1/P2
- 设计方法与 Web 专项维度（表单校验、列表 CRUD、导航路由、空态/错误、弹窗、权限、会话等）详见 [playwright-cli-testcase/references/test-methods.md](playwright-cli-testcase/references/test-methods.md)

## 5. 不做的事

- 不初始化 Playwright 测试工程、不生成 `.spec.ts`
- 测试点未确认不导出用例
- 仅给 URL 时不先索要需求文档
- 「需求 vs 界面」不一致时不擅自选定验收基准
- 遇登录墙/验证码不绕过、不伪造

## 6. 环境要求

- Node.js（`npm install -g @playwright/cli@latest`）
- Python 3 + `openpyxl>=3.1.0`（仅 Excel 导出需要；XMind 导出无第三方依赖）
