# ApiAutoTest2.0 使用说明

API 自动化测试套件（Claude Code / Cursor 通用），由 **6 个技能组成管道式流水线**：从源码扫接口文档 → 设计业务场景 → 生成可执行用例 → pytest 执行 + Allure 报告 → 报告服务，外加配置助手。**核心数据流是 `cases.json`**（顶层 `dependencies` + `cases`），各技能围绕它衔接。

---

## 1. 技能清单与管道

| 技能 | 职责 | 核心产物 |
|------|------|----------|
| `api-doc-generator` | 扫 Java/Go/Python/Node 源码提取 HTTP 接口定义 | `docs/api/api-docs[-<模块>].md` 或 `.json` |
| `api-scenario-generator` | 业务场景设计（单接口 + 串联），测试设计向 | `docs/<name>_scenario.json` + `_scenario.xlsx`（评审表） |
| `api-test-generator` | scenario + 接口文档 → 可执行用例（JSON+Excel 双产出） | `docs/<name>_cases.json` + `_cases.xlsx`（2-sheet） |
| `api-test-runner` | 执行 cases.json（pytest 参数化）+ Allure 结果 | `allure-results/`、执行汇总与修复建议 |
| `api-test-report` | 从已有 allure-results 生成/打开 Allure 报告；未安装则引导 | Allure HTML 报告 |
| `api-test-config` | 维护 `config/.env`（前置依赖变量 + DB 断言模板） | `config/.env` |

```
api-doc-generator ──► api-scenario-generator ──► api-test-generator ──► api-test-runner ──► api-test-report
   (源码→接口文档)        (文档→场景JSON/Excel)      (场景→cases.json/xlsx)    (执行+结果)        (Allure查看)
                                                                    ▲
                                                    api-test-config（.env 辅助，随时）
```

## 2. 核心契约：cases.json

```json
{
  "dependencies": [
    { "name": "dep_login_admin", "request": { "method": "POST", "path": "/auth/login", "body": { "username": "admin", "password": "ENV:ADMIN_PASS" } },
      "assert": { "status": 200, "checks": ["$.code==200 && $.data.token"] },
      "extract": { "token": "$.data.token" } }
  ],
  "cases": [
    { "id": "1", "name": "场景名", "enabled": true,
      "steps": [ { "name": "step_01_get", "request": { "method": "GET", "path": "/api/v1/user", "headers": { "Authorization": "Bearer DEP:dep_login_admin.token" } }, "assert": { "status": 200, "checks": ["$.code==200"] } } ],
      "assert": { "status": 200, "checks": ["$.code==200"] },
      "db_assert": [ { "name": "check_row", "sql": "SELECT id,status FROM orders WHERE id = STEP:step_02_post.orderId", "checks": ["rows_count==1", "row0.status==\"CREATED\""] } ] }
  ]
}
```

- **`request` 与 `steps` 互斥**（至少其一）；step 名唯一；仅执行 `enabled` 为真的 case
- **引用协议**：`ENV:KEY`、`DEP:depName.field`、`STEP:stepName.field`（可整串或嵌入字符串，如 `Bearer DEP:auth.token`）
- **id 规则**：cases 与场景 ID 均为纯数字字符串序号（`"1","2",...`），不用 `CASE-001` 等编码
- **checks 表达式**：`== != > >= < <=`，多条件 `&&`（兼容 `;`）
- **禁止占位体**：`{"example":1}`、`__RANDOM__` 等

## 3. 各技能要点

### api-doc-generator（源码 → 接口文档）
- 支持 Java（Spring 注解）/ Go（Gin、net/http）/ Python（Flask/FastAPI/Django）/ Node（Express/Koa/NestJS）
- 范围可指定：整个项目 / 模块目录 / URL 前缀；格式 `json` 或 `md`（默认 md）
- **必须写文件**（默认 `docs/api/`、`docs/api-json/`），非只在对话展示
- 统一 Endpoint 模型（path/method/参数/请求体/响应），可作 OpenAPI 中间层

### api-scenario-generator（场景设计）
- 固定产物两份：`docs/<name>_scenario.json`（根键 `cases`，**顶层 `dependencies`**）+ `_scenario.xlsx`（单 Sheet 含 `场景类型` 列）
- 覆盖策略：全模块、先单接口后串联；每接口至少 1 条正向；写操作补必填缺失/非法值/资源不存在/业务冲突；数值补边界
- **登录必须沉淀到顶层 dependencies**（如 `dep_login_admin`），不要每条 case 重复写登录
- 造数三层（准备→验证→清理），破坏性操作放末尾；禁止写真实账号密码
- 一键执行：`python .cursor/skills/api-scenario-generator/scripts/run_scenario_pipeline.py -n user`

### api-test-generator（生成执行用例）
- 输入：scenario.json + 接口文档；**由 Agent 按生成规则转换**（`scenario_to_json_plan.py` 已移除）
- 登录去重与 `DEP` 注入：同一用户只保留一条登录 dependency；特殊登录场景（测登录本身/重登/换号）允许留在 steps
- **DB 断言开关**：`DB_ASSERT_ENABLED=false` 或配置不完整 → 跳过 db_assert 输出纯 HTTP；启用时**必须先跑 `export_db_schema.py`** 查表结构再写 SQL
- SQL 中 `STEP:/DEP:/ENV:` 占位符**禁止手工加引号**（runner 自动按类型生成字面量）
- 14 项输出自检清单必须全部通过，再导出 Excel：
  `python3 .cursor/skills/api-test-generator/scripts/plan_json_to_excel.py -i docs/<name>_cases.json -o docs/<name>_cases.xlsx`
- Excel 2-sheet：`dependencies`（9 列）+ `cases`（steps_json/db_assert_json 为 JSON 数组字符串）

### api-test-runner（执行）★ 只执行不修改
- 入口：
  ```bash
  python ApiAutoTest2.0/api-test-runner/scripts/run_tests.py --cases-json <cases.json> [--base-url <url>] [--serve]
  ```
- 实现自包含（scripts/ 下 conftest.py + test_api.py），pytest 参数化每条 case；session 先跑 dependencies（拓扑排序）
- **红线**：不自动改断言、请求体、路径参数、依赖引用、账号密码；失败只输出「失败用例ID / 预期 vs 实际 / 根因判断 / 修复建议（高阻断·中数据不稳定·低断言优化）」
- 敏感信息走环境变量，不写入计划文件

### api-test-report（Allure 查看）
- 不执行测试，只从**已有** `allure-results` 生成/打开报告：默认 `allure serve allure-results`
- 未安装 Allure CLI 时不改环境，只给安装指引（macOS `brew install allure`）
- 脚本：`python .cursor/skills/api-test-report/scripts/serve_report.py [--no-open]`

### api-test-config（.env 助手）
- 维护 `config/.env`：必含 `BASE_URL`；按前置依赖梳理 `LOGIN_USER/LOGIN_PASS` 等变量
- **默认补齐 DB 断言模板且关闭**：`DB_ASSERT_ENABLED=false` + `DB_HOST/PORT/NAME/USER/PASS/CHARSET`
- 合并策略：只新增缺失变量，保留已有注释与顺序；不生成 `.env.example`

## 4. 典型使用流程

```text
1. 「扫描 backend/user-service 生成接口文档」          → api-doc-generator
2. 「根据接口文档生成测试场景」                          → api-scenario-generator（scenario.json/xlsx）
3. 「生成可执行用例」                                    → api-test-generator（cases.json/xlsx）
   （首次先配环境：「帮我配置前置依赖和数据库断言」       → api-test-config）
4. 「执行 docs/user_cases.json，base-url http://...」    → api-test-runner
5. 「打开 Allure 报告」                                  → api-test-report
```

## 5. 环境与依赖

- Python 3（pytest；generator 导 Excel 需 openpyxl 类依赖）
- Allure CLI（api-test-report；未装时只引导不自动安装）
- DB 断言（可选）：MySQL 连接信息走环境变量，启用前先 `export_db_schema.py`
- 敏感信息（账号密码）一律环境变量注入，不入库不入计划文件
