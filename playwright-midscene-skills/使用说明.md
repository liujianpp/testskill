# playwright-midscene-skills 使用说明

一套 **Playwright + Midscene 混合** 的 UI 自动化技能流水线（Claude Code / Cursor 通用），由 4 个编号技能组成：**探索出计划 → 生成代码 → 无头执行出报告 → 修复失败用例**。

核心思想：**稳定 DOM 用 Playwright locator；动态 UI（Canvas/WebGL 图表、closed Shadow DOM、跨域 iframe、图形验证码等定位不了的场景）降级用 Midscene Instant Actions（视觉模型驱动）**。这样脚本可在 CI 流水线、云端环境稳定运行（不依赖本地 AI Agent 的多模态能力）。

> 目录说明：`__MACOSX/` 为 macOS 打包残留，可删除。部署时复制 4 个技能目录（`00-` ~ `03-`）到 `.claude/skills/` 或 `.cursor/skills/`。

---

## 1. 技能清单与流水线

| # | 技能 | 职责 | 产出 | 禁止 |
|---|------|------|------|------|
| 00 | `00-playwright-explore-plan` | playwright-cli 有头探索界面，生成探索报告（用例矩阵 + 代码映射 + 每步 driver） | `tests/reports/{case-name}-report.md`、`tests/explore/{case-name}-*`（snapshot/截图/auth） | 禁止生成 spec 代码 |
| 01 | `01-playwright-gen-code` | 按探索报告生成/扩展测试代码（Playwright 为主，midscene 步混入 Instant Actions） | `tests/{case-name}.spec.ts`、`tests/pages/*.ts`、`tests/fixture.ts`、`tests/helpers/captcha.ts`、`.env.example` | 不探索、不跑测 |
| 02 | `02-playwright-run-report` | 无头执行测试，开 HTML 报告，做合规校验（矩阵通过数、video/trace） | Playwright HTML 报告（localhost:9323）、`midscene_run/report/` | 不做 heal |
| 03 | `03-playwright-heal` | 修复失败用例（Playwright 步修 locator，Midscene 步只改自然语言 prompt），**最多 2 轮** | 修复后的 spec/PO/helper | 修完不自动循环跑 |

```
@00 探索&计划 ──► @01 生成代码 ──► @02 执行&报告 ──失败且同意修复──► @03 修复 ──► 回到 @02 复跑
     (有头)                          (无头)                          (最多 2 轮)
```

各技能结束时只**提示**下一步（不自动串跑）。

## 2. 产物目录约定（被测项目内）

```
tests/
├── {case-name}.spec.ts            # 测试代码（01 生成）
├── pages/{PageName}.ts            # Page Object（稳定 locator）
├── fixture.ts                     # Midscene fixture（有 midscene 步时才建）
├── helpers/captcha.ts             # 图形验证码 helper（有验证码时）
├── auth.setup.ts                  # 登录 setup（测登录 + 业务 storageState 共存时）
├── reports/{case-name}-report.md  # 探索报告（00 产出，01/02/03 的契约源）
└── explore/{case-name}-*          # snapshot / 步骤截图 / auth.json（00 产出）
midscene_run/                      # Midscene 报告与缓存（gitignore）
.env / .env.example                # 模型配置（.env 不入库）
```

## 3. 关键契约

### 3.1 探索报告（00 → 01/02/03 的交接契约）
必须包含：**用例矩阵**（ID、名称、起始 URL、前置、步骤、数据、预期）、**用例 → 代码映射表**、每步 **driver**（`playwright` 或 `midscene`）+ locator/prompt + 降级 reason、备选 locator、断言点、auth 路径；涉及图形验证码时记录：图片定位、字符长度/字符集、刷新控件、失败文案、成功跳转；涉及弹窗时记录 dialog 可访问名。
**门禁**：矩阵未写入 report.md 不得进入探索 Step 2；01 无 report 不得生成代码。

### 3.2 定位优先级（探索与生成代码强制）
`data-testid` → role+可访问名称 → `id` → CSS 类+标签 → XPath（尽量避免）→ **降级 Midscene**（不硬扛脆弱 XPath）。
普通表单/按钮/表格/链接只要 testid 或 role+name 可用，一律写 Playwright。

### 3.3 Midscene 降级判定（满足任一 → `driver: midscene`）
Canvas/WebGL 目标不在 a11y tree；closed Shadow DOM；跨域 iframe；snapshot 无可用 ref；只有 hash class / 深层 XPath；图形验证码（读图用 `aiQuery`，输入框和登录按钮仍是 Playwright）。

### 3.4 Instant Actions 白名单（生成代码只用这些）
`aiTap` / `aiInput` / `aiHover` / `aiScroll` / `aiWaitFor` / `aiAssert` / `aiQuery`。
**禁止**：`aiAct`/`ai`/`aiAction` 整段流程、YAML 脚本、Tesseract/第三方 OCR 读验证码。

### 3.5 图形验证码通用模式
逻辑集中在 `tests/helpers/captcha.ts`（不在每条用例复制 prompt）；`aiQuery` 读图 + Playwright 填输入框；读码前清空输入框、对返回做 normalize；**分层重试**：读码格式不合格默认最多 3 次、提交后验证码类错误默认最多 5 次；位数/字符集/文案以探索报告为准，不写死。

### 3.6 存量项目硬约束（01）
已有 `playwright.config.ts` 或 `@playwright/test` 依赖时：禁止全量 `npm init playwright`；禁止整文件覆盖已有 PO/fixture/helper；config **只补缺**（`timeout: 90_000`、video/trace `'on'`、Midscene reporter），不重写 `projects`/reporter 整表；同 case-name 的 spec 原文件内 1:1 更新，不建平行文件。

### 3.7 合规校验（02）
矩阵通过数 = 探索报告矩阵行数（setup/其它 project 单独说明，不得混入总 passed）；每条矩阵用例必须有 video 与 trace；报告服务默认端口 9323（启动前先释放端口）。

## 4. 环境与依赖

```bash
# playwright-cli（00 探索 / 03 调试）
npm install -D @playwright/cli@latest
npx playwright-cli install

# Midscene（有 midscene 步时，01 或 02 均可补装）
npm install -D @midscene/web
```

`.env`（由 `.env.example` 复制，模型**必须支持视觉/多模态**）：

| 变量 | 说明 |
|------|------|
| `MIDSCENE_MODEL_API_KEY` | 模型 API Key（禁止入库） |
| `MIDSCENE_MODEL_BASE_URL` | OpenAI 兼容 endpoint |
| `MIDSCENE_MODEL_NAME` | 视觉模型名 |
| `MIDSCENE_MODEL_FAMILY` | 坐标处理族（与模型匹配） |

缺 key / 模型无视觉能力 → **阻塞**报告用户，不走 locator heal。

## 5. 各技能要点速览

**00 探索**：只读理解用例文件（txt/md/csv 直读、xlsx 提文本、xmind 用 `unzip -p file.xmind content.json`），无固定 schema，不确定就问；探索有头 `open --headed`；两种模式——A 直接打开、B seed attach（有登录/fixture 优先）；每步判定 driver；禁止用浏览器 MCP 替代 playwright-cli。

**01 生成**：前置门禁（report 存在且含矩阵/映射/driver）；先过 design-checklist 自检；矩阵 1:1 → 每个验证点一个 `test()`，禁止合并场景；`test.step('准备'/'操作'/'验证')`；敏感数据走 `process.env`；步骤 ≥5 或跨页用 PO；数据自建（`Date.now()`），不依赖易变种子。

**02 执行**：默认无头；跑前确认 video/trace 配置；`npm run show-report` 后台启动并告知地址；失败时在对话中直接询问是否修复（回复「是」→ 提示调用 `@03-playwright-heal`）。

**03 修复**：按 driver 分流——Playwright 步用 `playwright-cli attach + snapshot` 修 locator；Midscene 步**只改自然语言 prompt**（不补 XPath）；验证码错改 helper；模型问题阻塞上报；最多 2 轮，之后人工介入。

## 6. 与工作区其他套件的关系

- 与 `playwright-cli-testcase`（生成用例文档，不出代码）互补：本套件产出**可执行代码与报告**。
- 与 `browser-use-case-runner` / `browser-use`（LLM 逐条驱动浏览器执行自然语言用例）是两条不同技术路线：本套件是**代码化、可进 CI** 的方案。
