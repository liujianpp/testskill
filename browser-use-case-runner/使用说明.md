# browser-use-case-runner 使用说明

Web UI **用例执行器**技能（Claude Code / Cursor 通用）：把结构化用例（xlsx 表格 / Markdown / 对话中手动粘贴）交给 **有头 browser-use** 逐条执行——由 Agent 阅读自然语言步骤后驱动浏览器（LLM 驱动，非脚本映射），终端流式输出过程，最终产出 **Markdown 报告（PASS / FAIL / BLOCKED + 截图引用）**。

CLI 行为契约以 sibling 技能 [browser-use](../browser-use/SKILL.md) 为准；本技能定义的是**输入形态、执行节奏、当轮配置、留痕与报告**规范。

---

## 1. 输入：用例来源（三选一或组合）

| 方式 | 说明 |
|------|------|
| 表格 `.xlsx` | 首行表头；推荐列：用例编号/用例名称/功能模块/优先级/前置条件/测试步骤/测试数据/预期结果（脚本按表头名匹配） |
| Markdown `.md` | 每用例一个 `## <编号> <名称>` 二级标题 + 粗体标签子弹（模块/优先级/前置/步骤/数据/预期）；多步步骤用子列表 |
| 手动输入 | 用户对话中直接给字段（与 MD 子弹等价），Agent 内存组结构化列表，无需落盘 |

导出为 JSONL（统一中间格式，字段键：`id, name, module, priority, preconditions, steps, data, expected, source`）：

```bash
# 在被测项目仓库根目录执行
python3 .claude/skills/browser-use-case-runner/scripts/test_cases_export.py xlsx test-data/用户登录-测试用例.xlsx -o reports/cases.jsonl
python3 .claude/skills/browser-use-case-runner/scripts/test_cases_export.py md test-data/example-cases.md -o reports/cases.jsonl
```

## 2. 当轮 run-config（强制，先于一切浏览器操作）

每轮必须生成 `reports/run-config-<UTC>.json` 作为**当轮唯一真源**；skill 目录的 `runner-config.json` 仅是 `--defaults` 模板：

```bash
python3 .claude/skills/browser-use-case-runner/scripts/generate_run_config.py \
  --jsonl reports/cases-<标签>.jsonl \
  --source "xlsx:<相对路径或来源描述>" \
  --defaults .claude/skills/browser-use-case-runner/runner-config.json
```

关键字段：

| 字段 | 说明 |
|------|------|
| `sessionStrategy` | `single-session`（首条 open 后同会话连续）或 `fresh-per-case`（每条前 `close --all` 再 `headed open`） |
| `inferredSuiteKind` | 脚本启发式推断 `login` / `other`；**登录类默认 fresh-per-case，其他默认 single-session** |
| `videoRecording.enabled` | **默认 false（方式 1：关键步骤截图留痕）**；true 仅用户显式要整屏外部录屏时 |
| `userOverrides` | 记录用户对会话策略/录屏的确认 |

流程：导出 JSONL → 生成 run-config → **短问短答**确认（缺 URL 只问 URL；会话策略一行带过默认值；录屏默认**不问**）→ 写回 JSON 并打印 `RUN_CONFIG=<路径>` → 整轮只读此文件。**未生成 run-config 不得开始执行。**

> ⚠️ 注意：本仓库 `runner-config.json` 模板当前 `"enabled": true`，与 SKILL.md / references 声明的默认 `false`（方式 1）**不一致**——实际使用时建议将模板改回 `false`，或在每轮生成后核对 `videoRecording.enabled` 取值。

## 3. 执行节奏（默认）

1. **连续执行（依赖 sessionStrategy）**：终端按条输出阶段行 `[id] START` → `STEP n: ...` → `STATE: 一句话摘要` → `[id] RESULT: PASS|FAIL|BLOCKED`。`single-session` 下 PASS 且无未决人工步骤 → 自动下一条；`fresh-per-case` 下顺序执行但每条前重开浏览器。
2. **遇阻即停**（默认）：CLI 失败/超时/目标元素缺失、断言 FAIL 或 BLOCKED、需人工输入（验证码/短信/扫码/U 盾/合规敏感操作）→ 立即停止汇报，不擅自多轮重试。
3. **验证码三级兜底**：`screenshot` 落盘（打印 `CAPTCHA_SCREENSHOT=`）→ 视觉 Agent 识别（**须报置信度**）→ 停止等人工回复；不得伪造通过、不得绕过风控；提交后仍错须停下问用户。
4. **可选覆盖**（仅用户显式声明）：**逐条停顿**（每条含 PASS 后即停）；**失败也继续**（FAIL/BLOCKED 照实写报告后继续，CLI 硬错误仍停）。

## 4. 逐条执行要点（Agent 驱动）

- 每条先 `browser-use state` 拿索引再交互（`input`/`click`/`select`/`wait text`）；**索引跨页会变，禁止硬编码复用旧索引**。
- 受控输入（密码等）清空优先 `input <索引> ""`，避免 `eval` 改 DOM 与框架状态不同步。
- 断言对照「预期结果」与页面文案/`state`；无法自动判定（如「与产品文案一致」）→ **BLOCKED** 并写明原因。
- **留痕（方式 1 默认）**：关键步骤后 + 结论态（PASS/FAIL/BLOCKED 定稿前）各至少一张 `browser-use screenshot` 到 `reports/screenshots/<用例id>-step<n>.png` 与 `<用例id>-result.png`，终端打印 `SCREENSHOT=<路径>`，报告必须引用。

## 5. 外部整屏录屏（可选，默认关闭）

仅当用户**显式要**整屏/桌面录像时 `videoRecording.enabled=true`：打印 `VIDEO_RECORDING=enabled`（**非** browser-use 内置能力）→ Agent 全自动 `ffmpeg -version` 检测 → 缺失按 OS 安装（brew/winget/choco/apt/dnf）→ 后台启录（macOS avfoundation 取真实屏幕索引、Windows/Linux gdigrab/x11grab）→ `FFMPEG_OUTPUT=<路径>` → 再首次 `--headed open`。用户声明只用 OBS/系统录屏或 ffmpeg 失败 → 降级人工录屏确认。收尾 kill 录屏进程并在报告头记录像路径。

## 6. 报告产物

```
reports/
├── run-config-<UTC>.json                 # 当轮唯一真源
├── cases-<标签>.jsonl                     # 导出的用例
├── case-run-<时间>.md                     # ★ Markdown 报告
└── screenshots/
    ├── <用例id>-step<n>.png               # 关键步骤
    ├── <用例id>-result.png                # 结论态
    └── <用例id>-captcha.png               # 验证码（如有）
```

报告每用例一小节（编号、名称、结果、依据、截图路径），末尾汇总总数/PASS/FAIL/BLOCKED；报告头记 URL、用例来源、run-config 路径（及录像路径如有）。

## 7. 冒烟验证（首次接入建议）

1. 准备仅 1 条用例的 MD/xlsx（或手动粘贴一条）。
2. 走完整流程：导出 → 生成 run-config → 确认 → `browser-use --headed open <url>` → 执行 → 写报告。
3. 核对：headed 生效、截图落盘、报告路径符合预期。
4. 多条且未声明逐条停顿时默认连续；只想验单条可声明「只跑第一条」。

## 8. 限制与红线

- 不同页面结构须重新 `state`；`state` 无法给出验证码字符/Canvas 文字/纯像素信息时才走视觉兜底链。
- 默认节奏与用户当次明确指令冲突时，以**用户指令**为准。
- 测试环境优先关闭/固定验证码；生产环境风控不得绕过。
- 视觉识别可能误判，关键用例保留截图供人工复核。
- 不声称存在 `browser-use` 未文档化的录像/OCR 子命令。

## 9. 与工作区其他套件的关系

- **依赖** browser-use（CLI 契约）；与 spectest 通过 25 列 Excel → 8 列转换衔接（testflow 3B 支线，转换器 `testflow/convert_25col_to_ui_xlsx.py`）。
- 与 playwright-midscene-skills 是两条路线：本技能 **LLM 逐条驱动、无代码产物**，适合探索性/手工用例回归；后者**代码化可进 CI**。
