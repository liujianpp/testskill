# Markdown 用例格式

用于 `.claude/skills/browser-use-case-runner/scripts/test_cases_export.py md <file.md>`（在仓库根目录执行）或供 Agent 直接解析。

## 结构约定

每个用例一个二级标题，**第一行为 `## <用例编号> <用例名称>`**（编号与标题之间空格分隔；标题可省略则整段作为 `name`）。

其下使用**无序列表**，字段标签用粗体，与 xlsx 表头列语义一致：

```markdown
## TC-LOGIN-001 页面展示与标题

- **模块**: 用户登录
- **用例名称**: 页面展示与标题
- **优先级**: P2
- **前置条件**: 已打开登录页
- **测试步骤**:
  - 打开用户登录页面
  - 观察页面元素
- **测试数据**: "-"
- **预期结果**: 标题显示「用户登录」；存在用户名、密码、验证码输入框及登录按钮。
```

### 多行「测试步骤」

推荐使用子列表（如上）；也可使用同一条 `- **测试步骤**: ` 后紧跟多行，以缩进块书写（至少 2 个空格）：

```markdown
- **测试步骤**:
  1. 打开页面
  2. 点击登录
```

### 可识别的标签（不区分中英文键时优先中文）

- `模块` / `功能模块`
- `用例名称` / `名称`
- `优先级`
- `前置条件`
- `测试步骤`
- `测试数据`
- `预期结果`

`用例编号` 若单独成项，可写 `- **用例编号**: TC-LOGIN-001`；否则取自 `##` 行首 token。

## 手动输入（对话内）

用户未给文件时，可采用**相同子弹字段**，由 Agent 拷贝为内部结构与 JSONL 行字段一致，不必落盘。

示例用户消息：

```
用例1:
- **用例编号**: TC-DEMO-001
- **测试步骤**: 打开首页，检查标题包含「欢迎」
- **预期结果**: 标题可见
URL: https://example.com
```

Agent 将 `id/name/steps/expected` 等补齐后按本 skill 主流程执行。
