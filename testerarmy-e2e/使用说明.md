# testerarmy-e2e 使用说明

基于开源 AI E2E 框架 [tester-army/e2e](https://github.com/tester-army/e2e) 的五技能套件（Claude Code / Cursor 通用），覆盖「初始化 → AI 探索写草稿 → 执行 → 修复 → 报告」的端到端测试闭环。所有操作都发生在**用户的应用目录**（不在 skill 目录安装 e2e）；五个技能均设 `disable-model-invocation: true`，**须用户显式调用**。

---

## 1. 五技能与流水线

| 技能 | 职责 | 不做 |
|------|------|------|
| `e2e-init` | 初始化脚手架：选引擎（Web/Mobile）+ 选模型厂商（6 家），写 `e2e.config.ts`、`.env`（带注释）、npm scripts；然后**停手让用户填 API Key** | 不跑 explore/run |
| `e2e-explore-draft` | 输入需求/用例/URL → 一句一条 charter → `e2e explore` 探索 → 落 `*.e2e.ts` 草稿（标 draft） | 默认不执行 |
| `e2e-run` | 执行指定测试文件（默认不全量），出 MD+HTML 报告 + 对话摘要失败原因 | 不改脚本/定位器 |
| `e2e-fix` | 依据失败报告/trace/用户描述修复测试脚本与定位器；同一失败点最多改 **2 轮** | 默认不重跑、不改业务代码 |
| `e2e-report` | 从 `.e2e/report.json` 生成 MD + 单文件 HTML 报告（含证据链与视频内嵌） | 不执行测试 |

```
@e2e-init ──► @e2e-explore-draft ──► @e2e-run ──失败──► @e2e-fix ──► 回 @e2e-run 验证
                    （报告可随时 @e2e-report 或 npm run report:e2e）
```

## 2. e2e-init 要点

- **必选两项**（未选齐不动手）：引擎 `Web` / `Mobile`（平台按 OS 自动定：darwin→ios，否则→android，不追问）；厂商 `DeepSeek / OpenAI / Claude / 通义千问 / 智谱 GLM / 月之暗面 Kimi`
- **静默默认（不问）**：Web `APP_URL` 默认 `http://localhost:3000`；Mobile `E2E_BUNDLE_ID` 占位 iOS `Settings` / Android `com.android.settings`
- 脚手架命令：`npx e2e init --yes --engine <web|mobile> --skills none --mcp none --install`（pnpm/bun 用 dlx/bunx）；无 package.json 先生成最小模板
- 按厂商+引擎块改写 `e2e.config.ts`，文件顶部加 `process.loadEnvFile('.env')`；复制 `scripts/e2e.mjs` + `e2e-report.mjs` 并写入 npm scripts（`test:e2e` / `explore` / `report:e2e`）
- `.env` 逐键带 `#` 注释；`.gitignore` 补 `.env`、`node_modules/`、`.e2e/`；**Key 由用户本地填**，禁止写进对话/仓库
- 完成后明确停手：不探测 explore（避免未设 Key 刷 `MODEL_PROVIDER_FAILED`）

## 3. e2e-explore-draft 要点

- **输入三分支**：有需求/用例（可带地址）→ 拆 1–N 条一句 charter；只有地址 → 主成功路径 charter；都没有 → 只问不探索
- 探索命令（`.env` 的 `E2E_HEADED` 决定是否 `--headed`，用户口头要求优先）：
  ```bash
  npx e2e explore '<charter>' --max-steps 8 [--headed]
  ```
- **登录态复用判定**：同账号 ≥2 条业务主路径需登录（Web 且引擎支持 session）→ 先落 `auth.setup.e2e.ts`（`session.save`），业务 charter 用 `--session <name>` 且**不再写登录步骤**；否则不复用
- 草稿写法：一条主路径/用例一个 `test`；已知控件优先 `screen` + `expect`，多步一果用一次 `agent.act` 紧跟断言；**提示词默认中文**、控件名保持屏幕原文；文件头标 `draft`；每个 await 都要带；密码只走 `credentials`
- **遇付费/删除/真实订单等不可逆操作：停下问，不继续**

## 4. e2e-run / e2e-fix / e2e-report 要点

**e2e-run**：默认只跑用户点名文件或上一轮草稿（不全量）；`npx e2e run tests/<file>.e2e.ts [--headed]`；跑后自动或手动出报告，对话只摘「通过/失败/跳过数 + 每条失败的标题/错误码/一句原因/trace 路径」；禁止改 `tests/` 与自动改稿循环。

**e2e-fix**：输入三选一（run 的失败摘要 / `reports/e2e-report-*.md` / `.e2e/report.json`+trace / 用户描述）；只改测试脚本、定位器、setup/session；缓存可能过时时提示下次加 `--no-cache`；同一失败点最多 2 轮无进展即停。

**e2e-report**：优先 `npm run report:e2e`（自动）；产物 `reports/e2e-report-<YYYY-MM-DD>.md` + `.html`；**HTML 单文件**（CSS 内联、禁外链 CDN，离线可开）；须含用例一览 + 用例详情，失败块列可点证据（trace.md / video / 截图），有 webm 内嵌 `<video>`；不覆盖已有同名报告。

## 5. 环境变量速查（应用目录 .env）

| 变量 | 说明 |
|------|------|
| 厂商 API Key（按所选厂商命名） | 用户本地填写，禁入仓库 |
| `APP_URL` | Web 被测地址（默认 localhost:3000） |
| `E2E_BUNDLE_ID` | Mobile 应用包名（占位 Settings） |
| `E2E_HEADED` | `1` 有头 / `0` 无头（run 与 explore 共用） |
| `E2E_VIDEO` / `E2E_TRACE` | 默认 `retain-on-failure` |
| `E2E_USER_<NAME>_PASSWORD` | 测试账号密码，config 中以函数引用 |

## 6. 典型使用流程

```text
1. 「初始化 e2e，引擎 Web，厂商 DeepSeek」              → e2e-init（然后自己填 .env Key）
2. 「按这份 PRD 探索并写草稿，地址 https://xxx」          → e2e-explore-draft
3. 「跑 tests/order.e2e.ts」                             → e2e-run
4. 失败 → 「按报告修复」                                  → e2e-fix → 再 e2e-run 验证
5. 「导出报告」                                           → e2e-report（或 npm run report:e2e）
```
