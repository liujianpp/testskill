# 测试视角评审维度清单（5 维）

严重级别：`阻断`（无法设计/执行关键测试前必须补齐） / `重要`（测试设计前应处理） / `建议`（可排期完善）。

每个维度先给结论（通过 / 有条件通过 / 不通过），再列问题。无问题时写「未发现问题」。

聚焦「能不能测、怎么判过、漏测与阻塞在哪」，不做完整产品完整性/体验评审，也不展开写全量用例。

---

## 1. 可测性与验收标准

- [ ] 核心需求可写成可判定的验收/测试条件（Given/When/Then 或等价表述）
- [ ] 成功 / 失败有明确可观察结果（页面、接口、数据、消息、日志等）
- [ ] 避免「体验良好」「适当处理」「正常完成」等不可判定表述
- [ ] 关键阈值、阈值、数量、时限有数字或可核对指标（若适用）
- [ ] 验收标准覆盖主路径，而非仅复述功能名

**阻断示例**：核心功能无法写出任何可判定验收条件。  
**重要示例**：有验收条目，但结果不可观察或过空泛。

---

## 2. 边界与异常

- [ ] 空值、超长、非法、特殊字符等输入边界
- [ ] 权限不足 / 未登录 / 角色错误
- [ ] 失败、超时、重试、部分成功
- [ ] 并发、重复提交、幂等
- [ ] 上限、配额、分页、临界值
- [ ] 破坏性操作（删除/撤销/回滚）的确认与失败表现

**阻断示例**：支付、删除等资损/不可逆路径完全无失败与边界说明。  
**重要示例**：主路径有说明，关键异常分支缺失。  
**建议示例**：次要字段缺个别边界。

---

## 3. 场景与状态

- [ ] 主流程步骤完整，可据此设计场景用例
- [ ] 关键分支（取消、中断、返回、二次进入）是否交代
- [ ] 状态定义清晰（有哪些状态、如何迁移、终态是什么）
- [ ] 角色差异场景（不同权限看到/做到的不同）是否可区分测试
- [ ] 多端/多入口若存在，路径差异是否可测

**阻断示例**：无主流程且无状态说明，无法设计场景。  
**重要示例**：有主流程，但关键状态迁移或分支缺失。

---

## 4. 数据与环境依赖

- [ ] 测试数据前提（账号、配置、开关、初始化数据）是否说明
- [ ] 外部依赖（第三方、上下游接口、消息、定时任务）是否标明
- [ ] 环境差异（测试/预发/生产限制、能否造数、能否 mock）是否可知
- [ ] 时间相关（定时、过期、活动窗）是否可在测试环境模拟
- [ ] 清理/回滚数据是否有要求（若适用）

**阻断示例**：强依赖外部系统且无任何测试/联调说明，导致无法开测。  
**重要示例**：依赖存在，但造数或环境约束未写清。

---

## 5. 测试阻塞点

- [ ] 文档中的开放问题是否会卡住用例设计或执行
- [ ] 规则矛盾、术语冲突导致无法判定预期
- [ ] 缺少权限/账号/工具导致无法验证
- [ ] 不可测点是否显式标出（及替代验证手段）
- [ ] 回归影响面是否提示（改动模块、共用能力）

**阻断示例**：存在未决规则且直接决定通过/失败判定。  
**重要示例**：可测，但回归范围或替代验证未说明，易漏测。  
**建议示例**：次要开放问题不影响主路径测试。
