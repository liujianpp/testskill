# miniprogram 三件套使用说明

微信小程序 UI 自动化技能套件（Claude Code / Cursor 通用），由 **miniprogram-script-author（写脚本）+ miniprogram-run（执行）+ miniprogram-shared（共享约定）** 组成。技术栈：**miniprogram-automator + 微信开发者工具模拟器 + Jest**，产出可执行的小程序 UI 自动化 spec 与执行报告。

两个执行型技能均设置了 `disable-model-invocation: true`——**需用户显式调用**（`@miniprogram-script-author` / `@miniprogram-run`），不会被动触发。

---

## 1. 三件套职责

| 技能 | 职责 | 产出 | 不做 |
|------|------|------|------|
| `miniprogram-script-author` | 读用例（Excel/MD/XMind/文本）→ 模拟器采 WXML inspect → 逐条生成 Jest describe → 维护 suite.json | `miniprogram/tests/<模块>/<模块>.spec.js`、`miniprogram/suite.json`、`miniprogram/inspect/run-<RunId>/*.wxml` | **不执行**正式用例 Jest、不下 PASS/FAIL 结论、不写批量报告 |
| `miniprogram-run` | 执行既有 spec（单条/整套），写台账与 artifacts、Session 批量报告 | `reports/miniprogram-executions.md`、`reports/miniprogram-report-<sessionId>.md/.html`、`artifacts/<session>/<caseKey>/**` | 不从零写用例 spec |
| `miniprogram-shared` | 无 SKILL.md 的纯共享层：仓库约定（conventions.md）、选择器规则（selectors.md）、脚手架（scaffold.sh）、模板（templates/）、本机配置（miniprogram.local.config） | 脚手架与规范文档 | — |

## 2. 两步工作流

```
@miniprogram-script-author（探索 + 写 spec + 维护 suite）
        │  交付时注明「待 @miniprogram-run 校验」
        ▼
@miniprogram-run（suite 逐条执行 + 台账 + 伪 Trace + Session 报告）
        │  失败时：读 artifacts 日志定位，修订 spec 交回 @miniprogram-script-author（至多重试 2 次）
        ▼
   循环直至全绿
```

## 3. 安装与初始化（首次使用）

1. **放置技能**：三个技能目录放到 `<项目>/.cursor/skills/`（或 `.claude/skills/`），三者须同级，父路径记为 `<skills-root>`。
2. **脚手架**：在小程序**自动化仓库根**（含/将含 `miniprogram/` 的目录）执行：
   ```bash
   bash <skills-root>/miniprogram-shared/scaffold.sh .
   ```
   拷贝 `scripts/`（miniprogram-launch.js、capture-wxml.js、parse-testcases.js）、`miniprogram/tests/helpers/`、`jest.config.js`、`jest.setup.js`、空 `suite.json`。
3. **配置**：复制 `miniprogram.local.config.example` → `miniprogram.local.config`，填写 `projectPath`（小程序工程路径，必填）与 `cliPath`（微信开发者工具 CLI 路径，必填，或改用 `wsEndpoint`）。**勿提交 Git、禁止臆造路径**。
4. **依赖**（仓库根）：
   ```bash
   npm install --save-dev jest@^29.7.0 miniprogram-automator@^0.12.1 xlsx@^0.18.5
   ```
5. **凭据**：设置 `MP_ACCOUNT` / `MP_PASSWORD`（可选 `MP_ID_CARD`）环境变量；模板 helper 不写死账号。
6. **开发者工具**：自行开启服务端口并 `cli auto`（或配置 `wsEndpoint` 连接已打开的工具）。

## 4. 用户仓库目录约定

```
<自动化仓库根>/
├── scripts/                        # scaffold 拷贝（launch / capture-wxml / parse-testcases）
├── miniprogram/
│   ├── suite.json                  # ★ 唯一编排源：cases[] 按 order 排序
│   ├── tests/<模块>/<模块>.spec.js  # 一模块一文件；一条 TC 一个顶层 describe（describe 名以用例 ID 开头）
│   ├── tests/helpers/              # auth.js（ensureLoggedIn/forceLogin）、trace.js、screenshot.js
│   ├── inspect/run-<RunId>/        # WXML 快照 + .meta.json（写 spec 的唯一依据）
│   └── probes/run-<RunId>/         # 导航探针（仅到达页面，无业务断言）
└── reports/
    ├── miniprogram-executions.md   # 跨 Session 累积台账
    ├── miniprogram-report-<sessionId>.md / .html
    └── artifacts/<sessionId>/<caseKey>/{jest-results.json, console.log, screenshot.png?, trace/}
```

模块目录按业务划分（示例：`auth` / `home` / `maintenance` / `profile`）。

## 5. miniprogram-script-author 要点

- **交错快照**（Act → Snapshot → Write）：界面每次有意义变化，采 WXML 落盘 inspect，再从 inspect 写 spec。**禁止未对照快照就写 `page.$()` / `tap()` / `expect()`**。
- **强制流程（多 TC 串行迷你闭环）**：每条用例独立走「解析 → 补采缺口 → 写 describe 落盘 → 更新 suite.json」→ 再下一条；一条一闭环。
- **用例输入**：Excel 用 `node scripts/parse-testcases.js --input cases.xlsx --out cases.json`；MD/文本直接解析；XMind 引导导出 md。每条须含 `id/title/order/steps/expected`。
- **采集**：
  ```bash
  node scripts/capture-wxml.js --page /pages/login/login --out miniprogram/inspect/run-<RunId>/登录页_<YYYYMMDD-HHmm>.wxml
  ```
  路径从 `miniprogram.local.config` 读取；只采本条会用且仓库不能支撑的页面（够用即停，可复用历史 inspect）。
- **spec 生成规则**：`launchMiniProgram()` 启动；顺序 启动 → `createTrace` → 登录 → `trace.step` 包裹关键操作/断言 → `afterAll` `flush`；业务用例 `ensureLoggedIn`（会话复用），测登录流才 `forceLogin`；每条独立顶层 describe + 各自 beforeAll/afterAll。
- **反模式禁令**：禁止一 TC 一文件、禁止并行 automator（同模拟器同时只能一个 launch/Jest）、禁止业务用例每条 `clearStorage` 重新登录、禁止仅凭 Excel 写选择器。
- **阻塞处理**：探索穷尽仍缺材料时不得落盘可执行 spec，输出阻塞原因 + 缺失清单 + 用户下一步，不虚构路径。

## 6. miniprogram-run 要点

在**仓库根**执行：

```bash
<skills-root>/miniprogram-run/run-with-reports.sh <子命令> [参数]
```

| 子命令 | 用途 |
|--------|------|
| `suite` | 读 `miniprogram/suite.json`，逐条按 `cases[].id` 用 `--testNamePattern` 跑对应 describe；默认失败后继续、同一 Session |
| `suite --from TC-MP-003` | 从该条起续跑（优先匹配 cases[].id；会新开 Session） |
| `single <spec.js>` | 跑整个模块文件（模块级调试）+ 独立 artifact + 台账 |

`miniprogram-run.config`（与 run 技能同目录，可编辑）：

| 配置 | 默认 | 说明 |
|------|------|------|
| `RECORD_TRACE` | `true` | 伪 Trace：步骤 meta/wxml/截图 → `artifacts/.../trace/` |
| `RECORD_SCREENSHOT` | `false` | 收尾整页截图（走 `miniProgram.screenshot`） |
| `OPEN_HTML` | `true` | 执行后自动打开批量 HTML 报告 |
| `STOP_ON_FAIL` | `false` | `true` 时遇失败即停（后续 NOT_RUN，可 `--from` 续跑） |

失败排查：读 `artifacts/<session>/<caseKey>/` 下 `console.log`、`jest-results.json`、`trace/viewer.html`；修订 spec 须交回 `@miniprogram-script-author`，至多重试 2 次。

## 7. 选择器铁律（selectors.md 摘要）

1. 每个关键页须有 **WXML inspect 依据**（仓库 inspect → 用户粘贴 WXML → 已核对记录；禁止仅凭 Excel/口头步骤）。
2. 优先级：`id` / `data-*` > 经 inspect 核对的 class > `$$()` 文本过滤（兜底）> 禁止纯坐标/未验证深层链。
3. **自定义组件内元素必须 `element.$()`**（先 `page.$('custom-comp')` 再 `.inner`），`page.$()` 不能跨组件。
4. 动态列表用 `$$()` 遍历 + `text()` 过滤。

## 8. 已知限制（重要）

- miniprogram-automator **不支持** Playwright 级 video / trace.zip → 用**伪 Trace**（步骤 meta + WXML + 尽力截图 + viewer.html）作为证据链。
- 截图只能 `miniProgram.screenshot({ path })`（Page 无此 API，仅模拟器可用）。
- 登录相关步骤（`ensureLoggedIn` / `forceLogin` / 页面 path 含 `login`）Trace 跳过 png，仍落 meta/wxml。
- automator API 不臆造；无日志依据不得宣称 PASS。

## 9. 交付边界（PACKAGING.md）

分发只发三个技能目录（shared 含 `.example` 配置与 templates）；**禁止**随包分发 `miniprogram.local.config`（本机路径）、业务 spec/inspect/reports、用例 Excel 与账号明文。
