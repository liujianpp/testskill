## 🚀 SpecTest 8 步工作流

### 完整流程概览

```
1. test-new（新建变更）
   ↓
2. test-analysis（智能分析）
   ↓
3. test-points（生成测试点）
   ↓
4. test-generate（生成测试用例）
   ↓
5. test-review（评审质量）
   ↓
6. test-fix（修复问题）
   ↓
7. test-report（生成报告）
   ↓
8. test-archive（归档变更）
```

### 各步骤详细说明

#### 步骤 1: test-new（新建变更）

**功能**：创建新的测试变更目录

**输出结构**：

├── db_info/                # 数据库配置
│   └── db_config.json     # 数据库连接
├── artifacts/              # 生成的测试用例
│   ├── testcases.json     # JSON 格式
│   └── 优惠券测试用例.xlsx # Excel 格式
└── review/                 # 评审报告
    └── review_report.md   # 评审结果

## 🔧 关键技术实现

### 1. 字段映射机制

**问题**：旧格式使用（name, type, expected），新格式使用（title, test_type, expected_result）

**解决方案**：在 `generate_excel.py` 中实现 `get_field()` 函数

```python
def get_field(tc, field_name):
    """获取测试用例字段，支持多种字段名映射。"""
    field_mappings = {
        "title": ["name"],
        "test_type": ["type"],
        "expected_result": ["expected"]
    }

    # 优先使用直接字段名
    if field_name in tc and tc[field_name]:
        return tc[field_name]

    # 查找映射字段名
    if field_name in field_mappings:
        for mapped_name in field_mappings[field_name]:
            if mapped_name in tc and tc[mapped_name]:
                return tc[mapped_name]

    # 未找到，返回空字符串
    return ""
```

**优势**：
- 向后兼容旧格式
- 优先使用新格式
- 易于扩展新的字段映射

### 2. 三种生成模式

**from-specs**（简单转换）
- 输入：`specs/*.md` 测试点文件
- 处理：解析 Markdown，提取测试点，转换为 JSON
- 输出：`testcases.json`

**from-api**（智能生成）
- 输入：`project_info/api_list.json` API 文档
- 内部调用：testcase-design-api 能力
- 处理：
  1. 解析 OpenAPI/Swagger 规范
  2. 查询数据库表结构
  3. 智能生成正向、负向、边界、安全测试
  4. 为每个用例生成验证 SQL
- 输出：`testcases.json`

**from-feature**（智能生成）
- 输入：`project_info/feature_list.md` 功能清单
- 内部调用：testcase-design-functional 能力
- 处理：
  1. 解析 Markdown 功能清单

  3. 智能生成覆盖多种场景的测试用例
  4. 为每个用例生成验证 SQL
- 输出：`testcases.json`
