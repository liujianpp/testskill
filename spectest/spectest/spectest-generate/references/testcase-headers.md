# 标准功能测试用例表头定义

> 表头以 `D:\testcase\测试用例管理.xlsx` 为准，新增关联需求ID、用例版本，共 25 列。

## 标准列定义（25 列）

| 列 | 列名 | Key | 必填 | 取值说明 | 可否为空 |
|----|------|-----|------|---------|---------|
| A | 系统/项目 | project | 可选 | 所属系统或项目名称，如"物流平台"、"LSP系统" | 可空 |
| B | 模块 | module | ✅ | 业务模块名，对应功能清单一级标题，如"地址管理" | 不可空 |
| C | 功能 | feature | ✅ | 功能点名称，对应功能清单二级标题，如"地址搜索" | 不可空 |
| D | 测试项 | test_item | ✅ | 从功能细化出的具体测试检查项，描述性文字，如"关键字模糊搜索准确性"、"空关键字处理"、"数据库记录一致性" | 不可空 |
| E | 用例标题 | title | ✅ | 简洁的动词短语，清晰描述测试意图 | 不可空 |
| F | 前置条件 | preconditions | ✅ | 执行前需满足的条件：账号状态、页面位置、数据库数据状态 | 不可空 |
| G | 涉及到数据库表 | db_tables | 可选 | 本用例涉及的数据库表，如 lsp_dev.lsp_address_suburb | 可空 |
| H | 测试数据 | test_data | ✅ | 具体的输入数据，如搜索关键字、表单内容 | 不可空 |
| I | 测试步骤 | steps | ✅ | 按序编号，每步包含：页面 + 控件 + 操作 + 期望中间状态 | 不可空 |
| J | 预期结果 | expected_result | ✅ | UI层断言 + 数据层验证（含验证SQL期望值说明） | 不可空 |
| K | 验证SQL | validation_sql | 条件 | 涉及数据准确性时必填；纯UI交互写 N/A（只读/交互功能） | 条件必填 |
| L | 实际结果 | actual_result | — | 执行后填写，设计阶段留空 | 可空 |
| M | 是否通过 | is_passed | — | 执行后填写：通过 / 未通过 / 阻塞；设计阶段留空 | 可空 |
| N | 预计工时(h) | estimated_hours | 可选 | 预估执行工时，单位：小时，如 0.5 | 可空 |
| O | 执行时间(年月日) | execute_date | — | 执行后填写，格式：YYYY-MM-DD；设计阶段留空 | 可空 |
| P | 测试进度(%) | test_progress | — | 执行后填写，0～100；设计阶段留空 | 可空 |
| Q | 用例类型 | case_type | ✅ | 固定填写：功能测试 | 不可空 |
| R | 用例优先级 | priority | ✅ | P0 / P1 / P2 / P3 | 不可空 |
| S | 是否回归用例 | is_regression | 可选 | 是 / 否；P0/P1 通常填"是" | 可空 |
| T | 是否阻塞上线 | is_blocker | 可选 | 是 / 否；P0 类严重缺陷相关用例填"是" | 可空 |
| U | 关联需求ID | requirement_id | 可选 | 禅道需求ID，如 RQ-001；多个用逗号分隔 | 可空 |
| V | API URL | api_url | 可选 | 关联的后端接口路径，如 /api/address/search | 可空 |
| W | BUG数 | bug_count | — | 执行后填写；设计阶段填 0 | 可空 |
| X | BUG未解决数 | bug_unresolved | — | 执行后填写；设计阶段填 0 | 可空 |
| Y | 用例版本 | case_version | ✅ | 整数版本号。全新功能（旧用例中无此功能）填 1；已有用例基础上新增或修改的用例填（旧最大版本号 + 1） | 不可空 |

## 用例版本（case_version）规则

| 场景 | 版本号规则 | 举例 |
|------|-----------|------|
| 功能清单中是全新功能（旧用例文档中无此功能） | 填 **1** | 新功能"地址批量删除" → 所有用例 version = 1 |
| 功能已有旧用例，本次新增了更多用例 | 填 **旧最大版本 + 1** | 旧用例 version 最高为 2 → 新增用例 version = 3 |
| 功能已有旧用例，本次对其中某条进行了修改完善 | 填 **旧最大版本 + 1** | 旧用例 version 最高为 1 → 修改后 version = 2 |

**版本号确定方法（SubAgent 执行）：**
1. 从工作区已有用例文件（`testcase/` 目录）中，按 `module + feature` 匹配当前功能点
2. 读取匹配到的所有旧用例的 `用例版本` 列，取最大值 `max_version`
3. 若无匹配（全新功能）：`case_version = 1`
4. 若有匹配（已有用例）：`case_version = max_version + 1`（新增或修改的用例均用此版本号）

---

## 测试项（test_item）说明

**测试项是从功能点细化出来的具体测试检查项**，使用描述性短语，明确说明本条用例检查的是什么。

示例（功能点=地址搜索）：
- 关键字模糊搜索准确性
- 空关键字时的全量展示
- 搜索结果与数据库记录一致性
- 特殊字符输入处理
- 未登录状态的访问控制

## 覆盖类型（test_type，内部字段，不导出为列）

SubAgent 还需输出 `test_type` 字段供行颜色区分，该字段不写入 Excel 列：

| 取值 | 含义 | 占比目标 | Excel行颜色 |
|------|------|---------|------------|
| 正向 | 合法输入，功能按预期执行（含数据展示、主流程验证） | ≥ 40% | 白色 #FFFFFF |
| 负向 | 非法输入、空数据、系统异常、错误提示验证 | ≥ 30% | 浅黄 #FFF2CC |
| 边界 | 边界输入值、空状态UI、最大分页等临界场景 | ≥ 20% | 浅蓝 #DDEEFF |
| 安全 | 越权访问、SQL注入、XSS等安全测试 | ≥ 10% | 浅橙 #FFE4CC |
| 权限 | 角色权限验证、未登录状态、权限边界测试 | ≥ 10% | 浅橙 #FFE4CC |

## 用例优先级标准

| 优先级 | 含义 | 是否回归 | 是否阻塞上线 |
|--------|------|---------|------------|
| P0 | 冒烟级，必须通过 | 是 | 是 |
| P1 | 核心，发版前必测 | 是 | 否（视情况） |
| P2 | 增强覆盖 | 否 | 否 |
| P3 | 边缘/低频，有时间再测 | 否 | 否 |

| 内容 | 样式 |
|------|------|
| 表头行 | #2E75B6（蓝）白字加粗，行高30 |
| 正向测试项行 | #FFFFFF（白） |
| 负向测试项行 | #FFF2CC（浅黄） |

| 冻结首行 | freeze_panes = A2 |

## 验证 SQL 规范

- 仅使用 SELECT（禁止 INSERT/UPDATE/DELETE）
- 含具体 WHERE 条件，定位测试产生或验证的数据
- 添加注释说明验证目的
- 纯UI交互功能（无数据写入）填写：N/A（只读/交互功能）

示例：
```sql
-- 验证地址搜索结果数量与数据库记录一致
SELECT COUNT(*) FROM lsp_dev.lsp_address_suburb
WHERE suburb_name LIKE '%上海%' OR district LIKE '%上海%';
-- 期望值：= 页面显示的搜索结果总数
```
