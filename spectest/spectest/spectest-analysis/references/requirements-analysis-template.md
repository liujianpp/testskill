# requirements-analysis 模板

需求分析模板与字段说明，供编写 requirements-analysis.md 时参考。

---

## requirements-analysis.md

**用途**：需求分析与可测项梳理，产出需求拆解、边界与异常、待澄清项。

```markdown
# 需求分析：<标题>

## 需求来源
- 需求文档/PRD/用户故事：路径或摘要

## 功能与可测项拆解
- 按功能或模块列出可测点

## 边界与异常
- 关键边界、异常输入、依赖条件

## 待澄清项
- 需与产品/开发确认的问题（如有）
**说明**：在需求分析过程中，识别出需要与产品/开发确认的问题。按照以下 6 个类别组织：

### 1. 业务逻辑
**关注点**：业务规则、约束条件、流程逻辑
- 业务规则是否有歧义或不完整？
- 约束条件是否清晰（如数值范围、时间限制）？
- 业务流程是否完整？是否有遗漏的分支？
- 不同业务规则之间是否有冲突？


### 2. 系统交互
**关注点**：系统间接口、数据流、第三方依赖
- 与哪些外部系统有交互？接口定义是否明确？
- 数据同步是实时还是批处理？
- 第三方服务不可用时的降级策略？
- 接口调用失败的重试机制？


### 3. 数据精度
**关注点**：数据类型、格式、精度要求
- 数值类型的精度要求（如金额、百分比）？
- 日期时间的格式和时区？
- 字符串长度限制？
- 数据库字段是否已定义？


### 4. 用户体验
**关注点**：UI交互、提示信息、错误处理
- 页面跳转逻辑是否明确？
- 错误提示信息的具体要求？
- 加载状态的处理？
- 移动端适配要求？


### 5. 性能与安全
**关注点**：性能指标、安全防护、并发控制
- 并发场景的性能要求（如TPS、响应时间）？
- 数据安全要求（加密、脱敏）？
- 防刷、防作弊机制？
- 权限控制粒度？


### 6. 测试环境
**关注点**：测试数据、环境配置、依赖服务
- 测试环境是否已搭建？
- 测试数据的准备方式（生产数据脱敏还是构造）？
- 依赖的第三方服务是否可在测试环境访问？
- 数据库表结构是否已创建？

```
