# 测试计划模板

测试计划模板与字段说明，供编写 `test-plan.md` 时参考。计划是策略 + 管理文档，指导后续测试点深度与优先级；覆盖矩阵与用例提纲仍写在 `design.md`，本文件不替代。

---

## test-plan.md

**用途**：说明本次测试如何组织（范围、策略、环境、人力与人天、进度、进出标准、风险、交付物）。

```markdown
# 测试计划：<标题>

## 目标与范围
- 对齐来源：proposal / requirements-analysis（路径或摘要）
- 测试目标：（一两句话，可引用 proposal）
- 在范围内：（模块/能力列表或摘要）
- 不在范围内：（如有）

## 策略与优先级
- 测试类型：（如功能、接口、兼容、回归等，按本变更实际选用）
- 覆盖深度策略：（如核心路径全覆盖、次要路径抽样；正/负/边界/安全侧重，可对齐
  覆盖率目标：正向≥40%、负向≥30%、边界≥20%、安全≥10%）
- 优先级策略：P0 / P1 / P2 划分原则；建议先测的模块或能力

| 模块/能力 | 优先级 | 覆盖深度 | 说明 |
|-----------|--------|----------|------|
| …         | P0     | 深       | …    |

## 环境与数据
- 测试环境：（如测试/预发；浏览器或客户端版本等）
- 依赖与账号：（如有）
- 测试数据准备：（如有）

## 人力与人天
- 角色与分工：（如测试负责人、执行人；人数）
- 人天估算：按阶段或模块估算，单位为人天；不明时可标「待确认」

| 阶段/模块 | 负责人 | 人天 | 说明 |
|-----------|--------|------|------|
| 需求分析/计划 | … | … | … |
| 测试点与用例设计 | … | … | … |
| 执行与缺陷跟进 | … | … | … |
| 报告与收尾 | … | … | … |
| **合计** | — | … | — |

## 进度与里程碑
- 计划周期：（起止或阶段；与人天合计、可用人力一致）
- 里程碑：（如计划评审 → 测试点 → 用例 → 执行 → 报告）

| 里程碑 | 计划完成 | 产出 | 占用人天（可选） |
|--------|----------|------|------------------|
| …      | …        | …    | …                |

## 进入标准 / 退出标准
- 进入标准：（如需求已分析、环境可用、待澄清项已关闭或可接受）
- 退出标准：（如 P0 全部通过、无未关闭严重缺陷等）

## 风险与应对
- 风险列表与应对（可含需求分析中的待澄清项影响、prd-review 评审报告中的阻塞点）

| 风险 | 影响 | 应对 |
|------|------|------|
| …    | …    | …    |

## 交付物
- 本变更预期交付：（如 test-plan.md、specs/*.md 测试点、design.md、
  artifacts/<name>_testcases.xlsx（25列）、report.md）
```
