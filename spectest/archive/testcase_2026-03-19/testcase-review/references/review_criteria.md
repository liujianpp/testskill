# 测试用例评审标准

## 评审维度

### 1. 完整性（Completeness）
- [ ] 测试用例编号是否唯一
- [ ] 用例标题/名称是否清晰描述被测功能
- [ ] 前置条件是否完整（环境、数据、账号等）
- [ ] 测试步骤是否完整且无歧义
- [ ] 预期结果是否明确、可验证
- [ ] 优先级/严重程度是否标注

### 2. 准确性（Accuracy）
- [ ] 测试步骤与需求描述是否一致
- [ ] 预期结果是否与业务规则吻合
- [ ] 接口参数/字段名称是否与API文档一致
- [ ] 数据库字段/表名是否与实际表结构一致
- [ ] 业务流程顺序是否正确

### 3. 覆盖度（Coverage）
- [ ] 是否覆盖正常流程（Happy Path）
- [ ] 是否覆盖异常流程（Error Path）
- [ ] 是否覆盖边界值（Boundary Value）
- [ ] 是否覆盖等价类划分
- [ ] 是否覆盖权限/角色场景

### 4. 可执行性（Executability）
- [ ] 测试步骤是否足够细化，可以直接执行
- [ ] 是否依赖其他未明确的测试用例
- [ ] 测试数据是否有具体示例
- [ ] 环境依赖是否可以满足

### 5. 可维护性（Maintainability）
- [ ] 用例描述是否清晰易懂
- [ ] 避免冗余步骤
- [ ] 是否与其他用例存在大量重复

---

## 常见问题清单

### 严重问题（需要修改）
1. **缺少预期结果**：测试步骤有，但没有写明预期结果
2. **步骤不可执行**：描述模糊，如"点击按钮"未说明哪个按钮
3. **前置条件缺失**：执行步骤所需的环境/数据未说明
4. **需求不一致**：测试用例与需求文档描述冲突
5. **字段名错误**：使用了不存在的数据库字段或API参数名

### 一般问题（建议改进）
1. **缺少边界值测试**：只有正常值，没有边界（最大值、最小值、空值等）
2. **缺少异常场景**：只有正向流程，没有负向/异常测试
3. **测试数据不具体**：使用了"任意数据"等模糊描述
4. **步骤粒度不均**：有些步骤过于笼统，有些又过于细碎
5. **重复冗余**：与其他用例高度相似

### 优秀用例特征
- 标题明确指出被测功能点和场景
- 前置条件详细，包含具体测试数据
- 步骤原子化，每步只做一件事
- 预期结果精确，有具体数值/状态
- 覆盖了正常、异常和边界场景

## 评审意见格式

**问题级别**：严重/一般/建议

**问题描述**：简明描述问题所在

**改进建议**：给出具体的修改方向

**示例**：
> [严重] 第3步"输入金额"缺少具体数值示例，且未说明预期结果中金额格式要求（如保留几位小数）。建议补充测试数据示例（如：输入999.99）并明确预期格式（如："显示¥999.99"）。

若用例质量优秀，评审意见可留空。
